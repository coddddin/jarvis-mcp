# OpenRig 소스 기반 협업 엔진 검증 — 2026-10-20

## 무료 API 배정·한도 전환 정책과 OpenCode/Gemini 조사

사용자는 새 OpenCode 경로에서 Ollama 대신 무료 API를 사용하고, 여러 에이전트의 배정·결과 공유·한도 전환까지 자비스로 자동화하도록 지시했다. provider_routing.py에 호출과 독립된 정책 모델·무료 우선 선택·요청 단위 누적 예약/최대3시도·결과 확정 계약을 추가했다. 한도 실패는 다른 검증된 무료 후보로 전환할 수 있고, 진행 중/불명확 timeout/이미 성공한 요청은 자동 재실행하지 않는다. 같은 후보는 해당 요청에서 반복하지 않으며 예약은 모델 전환에도 유지한다. 직렬화 후 누적 상태 유지·유료 후보 제외·실제 사용량 초과·중복 완료 등을 포함한 **19개 검사 통과**(0.12초). 구조 검사 통과. 이 단계는 정책 함수이며 자동 채팅/실행기/트랜잭션 저장 연결은 아직 미완료다.

OpenCode Desktop 바로가기와 동봉 CLI v2.0.32를 확인했다. 인증 목록은 비어 있고 사용 가능한 목록에 여러 free 모델이 있었다. 사용자는 데스크톱 앱에서는 직접 질문에 답변한다고 확인했다. 보이는 시험 창과 artifacts/opencode-live-workspace의 별도 설정으로 무료 모델 opencode/glm-5.3-flash-free를 호출했지만 provider.auth HTTP403 FreeTierError를 받았다. 결과 파일 artifacts/opencode-free-events.jsonl과 상태 파일을 보존했다. 모델 목록이나 앱 응답을 자동 호출 성공으로 보고하지 않는다. 앞선 Ollama 시험은 exit0이나 출력이 없어 검증 성공이 아니며, 이후 사용자 지시에 따라 새 경로의 Ollama 호출을 중단했다. 새 시험 설정은 opencode 제공자만 허용하고 도구·통합을 차단한다. 유료 모델·새 인증·전역 설정으로 전환하지 않았다.

403은 CLI 자체의 전면 제한으로 단정하지 않는다. 공식 저장소 [#51241](https://github.com/anomalyco/opencode/issues/51241), [#50627](https://github.com/anomalyco/opencode/issues/50627), [#56324](https://github.com/anomalyco/opencode/issues/56324)에 custom agent의 read/shell 차단과 같은 FreeTierError의 연관 보고가 있다. 현재 deny-all 설정과 겹치지만 실제 앱 모델/에이전트와 비교하지 못했으므로 확정 원인은 아니다. 도구 허용·클라이언트 위장으로 제한을 우회하지 않았다. 공식 지원되는 제안 전용 경로나 다른 무료 제공자 확인이 남았다.

Gemini는 읽기 전용 병렬 조사에서 표준 CLI/npm/설치 폴더/바로가기/프로그램 등록과 설정·인증 경로를 찾지 못했다. 다른 이름·위치의 설치 가능성이 있어 미설치로 단정하지 않으며 정확한 앱명/경로 확인이 필요하다. [공식 Gemini headless 계약](https://geminicli.com/docs/cli/headless/)과 무료 인증/쿼터 문서를 조사했지만 실제 연결·모델 호출은 하지 않았다. OpenCode와 Gemini는 아직 자동 배정 ready 후보가 아니다. 기존 채팅 담당과 범위/제약/정책 접점을 공유했고 공용 채팅·서버 파일은 수정하지 않았다.

## Claude Code 실제 연결 — 후속 검증

사용자 결제·연결 승인 후 WinGet 공식 Anthropic.ClaudeCode 2.1.302를 설치했고 사용자가 직접 OAuth 로그인을 완료했다. 인증 상태에서 로그인됨·claude.ai·Pro만 확인했으며 토큰·이메일·계정 원문은 기록하지 않았다. Windows PATH 갱신 전에도 native 설치를 찾도록 `.local/bin`과 고정 WinGet 패키지 경로 fallback을 추가했다. 기존 링크/작업공간 실행 파일 거부와 고정 도구 없는 호출 제한은 유지했다.

1. 실제 어댑터로 합성 add 함수 제안 1회 호출 성공. artifacts/claude-transport-verification.json에 제안 결과를 저장했다.
2. 실제 로컬 리드→local-researcher→claude-code-coder→로컬 검수→로컬 종합 흐름 확인. 해당 시험만 외부 호출을 최대 1회로 낮췄다. 검수가 보류돼 최종 `needs_user_input`, `external_call_limit`, 전체 5단계·외부 1회로 종료했다. 보존 파일 해시 검사는 ok였다. artifacts/claude-team-verification.json에 합성 요청·결과를 보존했다. 코드 실행·적용·사용자 파일 수집은 없었다.
3. native 발견과 Claude 고정 인자 검사 추가 후 협업 전용 **33개 통과**(4.45초). 실행한 외부 호출은 위 2회이며 구독 사용량을 소비했다. 기능 정확성 검증이나 Claude 개발 세션의 자유로운 파일 수정·Codex 앱 세션 메시지 접근을 뜻하지 않는다.

서버 담당에 실제 검증과 발견 변경을 공유했다. 이 세션은 HUD 서버를 재시작하거나 자동 외부 AI 선택 정책을 변경하지 않았다. 이미 실행 중인 서버는 담당의 다음 반영 전까지 이전 발견 상태를 유지할 수 있다. 앞선 절들의 Claude 미발견/미검증 표시는 당시 기록이며 이 후속 검증으로 갱신한다.

## 실제 실행

첫 시도는 로컬 Ollama가 중지돼 리드 추론이 실패했다. 실패를 완료로 처리하지 않았다. 설치된 Ollama를 백그라운드로 시작한 뒤, 사용자 데이터와 분리한 artifacts/hybrid-live-workspace에서 합성 요청을 실행했다.

1. 첫 실연결: 로컬 리드가 로컬 조사자·로컬 작성자·Codex 작성자에 배정했다. Codex native CLI가 실제 제안을 반환했고 로컬 검수·최종 취합도 수행됐다. 검수 판정은 보류였으며 계획에 중복 작성 작업이 생겼다.
2. 계획 지침에 최소 작업 수·명시된 작업 배정 존중·중복 방지를 보완하고 검수 지침에 제안 요청과 실제 테스트의 구분을 명시했다. 두 번째 실연결에서 **local-researcher@jarvis → codex-coder@jarvis → 별도 로컬 검수 → 로컬 리드 취합** 흐름을 확인했다.
3. 두 번째 실행에서도 작은 로컬 모델의 검수 판정이 보류였다. 최종 상태는 `needs_user_input`이며 성공으로 바꾸지 않았다. 모델 검수 자체에 부정확한 지적도 있어, 결과 품질이나 코드의 기능 정확성이 입증됐다고 보고하지 않는다.

Git 제외 artifacts/hybrid-live-verification.json에 실제 계획·담당자·각 결과·검수·최종 답변·로컬 추론 단계 시간을 저장했다. 최신 시험 conversation ID는 `d05e3552325a4849a91c4a31f9c1d02d`, request ID는 `ba19e07869b04511b4763f61332503f9`이다. 상태·결과는 임시 합성 작업공간의 DB에 보존했다. 입력은 add(a,b) 함수와 예제 제안 요청뿐이며 사용자 파일은 프롬프트로 수집하지 않았다. 제안 코드를 실행하거나 사용자 파일에 적용하지 않았다.

Codex는 설치된 executable과 기존 ChatGPT 인증을 사용했다. 새 API 키·구독·결제나 전역 MCP/후크/프로필 변경은 하지 않았다. Claude CLI는 발견하지 못했으므로 실제 Claude 협업은 미검증이다. 공식 CLI 옵션에 따른 어댑터 코드만 준비했다.

## 인수인계

엔진·운영자 CLI는 실행 가능하고 실제 로컬↔Codex 결과 전달을 확인했다. 화면 협업 모드·실시간 진행 표시·기존 개발 작업 적용 연결은 담당 세션과 협의 후 연결할 범위다. 운영 중 8788 화면 서버는 이 단위에서 재시작하지 않았다. 로컬 모델의 검수 품질, 자동 수정/재검수, Claude 준비, 실제 실행 QA 연결은 후속 과제다.

담당 분담·완성 계약·실행 결과는 채팅 개선 세션(01a15902-6510-7195-8f3c-06247779a0b5)에 도구로 정상 전달했다. 공용 파일을 다시 덮어쓰거나 화면을 임의 재시작하지 않았다.

## 수정·재검수 루프 추가 — 2026-10-20

로컬 리드가 검수 의견을 받아 기존 작업의 수정 또는 중단을 결정하도록 구현했다. 담당자·실행 환경을 유지하고 의존 작업도 다시 수행한다. 수정 최대 3회, 외부 호출 총 3회, 전체 단계 20회, 공유 기한 600초 중 먼저 도달한 상한을 적용한다. 작업 버전과 검수 원문은 덮어쓰지 않고 경로·SHA256과 함께 보존한다. 통신 실패의 자동 재시도나 코드 실행·적용은 추가하지 않았다.

- 최신 협업 전용 검사: **20개 통과**(1.99초). 수정 담당 유지, 의존 작업 재계산, 버전 보존, 잘못된 수정 ID 거부, 외부 호출 공유 상한, 로컬 최악 경로 20단계 중단을 포함한다.
- 직전 협업·채팅 호환 묶음: **46개 통과**(3.90초), 기존 Starlette/httpx 폐기 경고 1개. 이후 문맥 잘림 표시 보완과 20단계 검사 추가 후에는 위 협업 전용 검사를 실행했다. 각 검사 수를 합산하지 않는다.
- 실제 로컬↔Codex 시험: 수정 2회, 외부 호출 3회, 검수 3회, 전체 11단계 후 `external_call_limit`으로 중단했다. 로컬 작업 버전 1개와 Codex 작업 버전 3개가 남았다. 최종 상태는 `needs_user_input`이며 검수 통과나 함수 정확성의 증거가 아니다.
- 합성 요청 기록: artifacts/hybrid-corrections-c5cc98cc5a6c40f9a94aedf61dcd7943.json. conversation ID `c45f5e93d2ba40fabfcbf07b6a9b8127`, request ID `c5cc98cc5a6c40f9a94aedf61dcd7943`. 사용자 파일을 수집하거나 제안 코드를 실행·적용하지 않았다.

새 로컬 채팅 담당 세션 `01a15947-5ecd-7952-bd11-c4119a9fe577`에 추가 상태 필드와 판정 구분을 전달했다. 화면·공용 채팅 코드·서버는 해당 세션이 담당한다. 이 단위에서는 수정하지 않았다. Claude 실제 실행과 실행 QA 연결은 여전히 미검증이다.

### 최종 답변의 중단 안내 보완

모델 종합 입력에 종료 사유·수정 횟수·외부 호출 수를 전달하고, 실제 중단 사유와 횟수는 서버가 답변 첫머리에 확정적으로 붙인다. 답변 길이 제한으로 코드 실행·파일 적용 미수행 안내가 잘리지 않도록 끝부분 공간을 확보했다. 화면 조회 없이 CLI 답변만 읽어도 보류 이유를 확인할 수 있다. 변경 후 협업 전용 **20개 통과**(2.62초). 첫 검사에서 기존 답변 첫 문장 기대값 1개가 변경과 맞지 않아 실패했고, 중단 안내·미해결 경고를 함께 검사하도록 갱신한 뒤 통과했다. 실제 외부 호출 시험은 반복하지 않았다.

### 보존 기록 확인 CLI 추가

`HybridTeam.verify_history`와 운영자 CLI `verify --conversation-id --request-id`를 추가했다. 고정된 요청별 버전·검수 경로만 읽어 저장된 SHA256과 비교하며, 변경·누락·참조 경로 불일치를 구분한다. 기록이 없거나 불일치하면 검증 성공으로 보고하지 않고 CLI는 종료 코드 1을 반환한다. 모델 호출·작업 재실행·파일 수정은 하지 않는다. 경로 가드레일·일반 파일·단일 링크·64KiB 크기 제한을 적용한다. DB 자체 변조에 대한 진위 보장이나 기능 정확성 판정은 아니다.

변경 후 협업 검사 **22개 통과**(3.08초). 기록 확인 중 추론 금지, DB 불변, 내용 변경 탐지, 다른 경로 참조 거부, 누락 파일을 검사했다. 이전 실제 협업 요청의 작업 버전 4개·검수 기록 3개를 직접 확인한 결과 7개 모두 일치했다. 같은 요청에 운영자 CLI로도 `status=ok`, `team_status=needs_user_input`을 확인했다. 외부 유료 호출은 추가하지 않았고 공용 채팅·화면 코드는 수정하지 않았다.

### 협업 품질 묶음 — 검수 범위·결과 누락·실패 안내

후속 동시성 검사: 서로 다른 ChatStore/HybridTeam 인스턴스가 같은 승인 요청을 먼저 읽도록 동기화한 뒤 동시에 실행했다. SQLite claim 승자는 한 개뿐이고 계획 추론 1회·작업 버전 1개·전체 4단계만 실행됨을 확인했다. 나머지 호출은 claimed 오류로 거부됐다. 저장 상태와 파일 해시는 정상이며 기존 완료 결과를 실패로 덮지 않았다. 스레드에서 별도 인스턴스/연결을 경쟁시킨 검사로, 별도 OS 프로세스 장애·재시작 복구까지 실증한 것은 아니다. 최신 전용 **31개 통과**(4.33초). 실제 화면 코드를 읽는 Node 채팅/이벤트 테스트도 **11개 통과**(71ms), 인증·늦은 조회·연결 해제·중복 이벤트 경계를 포함한다. 화면의 새 종료사유 매핑은 소스에서 확인했으며 실제 브라우저 확인은 담당 세션이 진행한다. 제품 코드 변경 없이 회귀 검사만 보강했고 모델 호출·서버 재시작은 하지 않았다.

사용자의 묶음 진행 지시에 따라 agents/team.py와 tests/test_hybrid_team.py에 함께 반영했다.

- 원문 1500자 초과로 검수 문맥이 잘린 경우 전체 검수 통과를 차단한다. 원래 모델 판정을 보존하고 `review_context_truncated`/`review_context_limit`으로 사용자 확인을 요청한다. 누락 문맥 때문에 추측 수정 루프를 돌리지 않는다.
- 종합 답변이 작업 코드를 생략해도 서버가 작업 원문을 별도로 포함한다. 총 6000자 예산을 각 작업에 나눠 배정하고 잘림 표시·전체 기록 안내·실행/적용 미수행 안내를 유지한다. 전체 출력은 저장소에 보존한다.
- 종합 단계의 ChatError/ValidationError는 보존 결과를 제공하는 사용자 확인 상태로 처리한다. `synthesis_failed`와 고정 사유를 기록한다. 중단 마커는 fallback 응답으로 우회하지 않는다.
- 실제 단계 실패에는 `failure.stage`, 고정 kind/message, 완료 작업 ID를 기록한다. 원시 예외·서비스 응답은 기록하지 않는다. 완료된 형제 작업과 파일을 보존한다.

전용 **30개 통과**(4.10초), 이후 최신 채팅 코드와 호환 묶음 **65개 통과**(5.57초, 기존 Starlette/httpx 폐기 경고 1개). 검사 수는 별개 실행이며 합산하지 않는다. 추가 사례는 검수 경계 1500/1501자, 코드 누락·종합 실패, 긴 작업 3개의 답변 공간/6000자 제한, 중단 마커, 단계 실패의 안전한 부분 결과 안내다. 테스트용 합성 추론을 사용했고 외부 모델 호출·코드 실행·파일 적용은 하지 않았다. 공용 채팅·화면·서버는 변경하지 않았다. 화면 담당에게 새 종료 사유 매핑과 추가 상태를 전달했다. 최신 코드의 실제 화면 반영은 해당 담당의 별도 확인 범위다.

### 이전 화면 검증 대조·Claude 가용성 확인

후속 검수 보완: 모델이 통과 표시와 미해결 문제 목록을 동시에 반환하면 서버가 유효 판정을 보류하도록 했다. 원래 표시 `model_reported_passed`·조정 이유 `policy_adjustment`와 문제 목록을 검수 기록에 보존한다. 수정 리드와 최종 종합에는 조정된 보류 판정을 전달한다. 일관된 통과는 유지한다. 관련 협업 검사 **24개 통과**(3.48초), 실제 모델 호출은 추가하지 않았다. 검수의 의미적 정확성이나 실행 QA를 보장하는 변경은 아니다.

사용자 요청으로 최신 협업·채팅 묶음을 재검증했다. 샌드박스에서 링크 생성 실패와 후속 로컬 통신 정체가 발생해 해당 실행을 중단하고 호스트에서 재실행했다. **53개 통과**(4.71초), 기존 Starlette/httpx 폐기 경고 1개. 전체 회귀 검사는 아니다.

화면 담당의 artifacts/chat-auto-live-verification.json 및 Phase 3 보고서를 대조했다. 실제 화면의 자동 로컬 협업 요청 `387611abf83345a6926d892a98658edc` / `118c7519c54347978a1ee4b5b3fa1b3a`는 team-local, 로컬 배정 3개, turn/team 모두 completed였다. 이 세션에서 운영자 verify로 작업 버전 3개·검수 1개 모두 저장 해시 일치를 확인했다. 화면 조작은 담당 세션이 수행했고 이번 세션은 기록을 대조했다. 모델 검수 완료이며 제안 코드 실행·적용의 증거는 아니다.

Windows 설치 조회에서 Claude 앱 2.42304.0.0을 확인했다. PATH와 일반적인 native/npm CLI 경로에서는 Claude Code를 발견하지 못했으므로 로그인 상태도 확인하지 못했다. 앱 설치와 CLI 이용 권한은 구분한다. [공식 설치 문서의 인증 조건](https://code.claude.com/docs/en/setup#authenticate)에 따르면 무료 claude.ai 요금제에는 Claude Code 접근이 포함되지 않는다. 사용자가 무료 요금제라고 밝혔으며 계정 구독을 직접 조회한 것은 아니다. 이번 검증에서 Claude/Codex 모델 호출·설치·로그인·결제는 수행하지 않았다.
