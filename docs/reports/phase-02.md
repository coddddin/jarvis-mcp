검증일: 2026-10-17 (Asia/Seoul)

## 상태

로컬 문서 인덱싱·벡터 검색은 구현 및 실제 실행 검증을 완료했다. Google 읽기 전용 연동 코드는 구현했으며 모의 API 테스트를 통과했다. 사용자는 OAuth 클라이언트 파일이 아직 없으므로 코드부터 구현하도록 지시했다. 따라서 **실계정 인증·실제 Google API 검증은 대기 중이며 Phase 2 전체를 실연동 완료로 선언하지 않는다.** Phase 3는 시작하지 않았다.

## 구현과 보존

- `knowledge.py`: UTF-8 문서 청크화, 로컬 해시 특징 벡터, 코사인 검색, SQLite 저장, 출처·줄 번호·발췌문, 오래된 결과 제외, 인덱스 삭제.
- `google_briefing.py`: Gmail 미열람 받은편지함 메타데이터와 한국 날짜 기준 기본 캘린더 일정의 읽기 전용 조회. 연결 상태, 날짜·개수 제한, 요청 시간 제한, API별 실패 표시.
- `google_auth_setup.py`: 운영자가 직접 실행하는 Desktop OAuth 로그인 도우미. 고정된 Google 인증 주소, PKCE, localhost 콜백, 읽기 전용 범위 및 원자적 토큰 저장.
- `server.py`: 새 MCP 도구 5개 추가. 기존 명령·시스템 상태·스크린샷 도구 3개를 유지했다. 모든 새 도구도 20회 예산과 중단 표시를 적용한다.
- `requirements.txt`와 전체 환경 버전 기록을 갱신했다. Google 토큰·클라이언트 파일을 Git 제외 목록에 추가했다.
- 개발 지침·원본 설계 기록을 유지했으며 `sources/` 및 동기화 파일을 수정하지 않았다.

## 실제 수행한 검증

- 변경 전 기준: 기존 테스트 34개 통과 (`34 passed in 1.68s`).
- 최종 전체: 54개 통과 (`54 passed in 2.19s`).
- 별도 서버 프로세스와 실제 stdio MCP 클라이언트로 초기 연결, 도구 8개 등록, 기존 도구 실행, 문서 인덱싱·한글 검색·인덱스 삭제, Google 인증 미설정 오류를 확인했다.
- 저장소 재생성 후 검색 유지, 한글·영문 정규화, 문서 변경·삭제 시 오래된 발췌문 제외, 원본 보존을 검사했다.
- 숨김·바이너리·잘못된 인코딩 처리, 입력 제한, 인덱싱 실패 시 기존 스냅샷 유지, 빈 디렉터리로 교체를 검사했다.
- 외부 경로·Windows 정션 우회, 하드링크 문서 및 DB 파일 우회를 차단하는지 검사했다.
- Google API는 모의 HTTP 응답으로 GET·리디렉션 금지·시간 제한·메일 메타데이터 범위·한국 날짜 경계·부분 실패 표시·오류 민감정보 비노출을 검증했다. 실제 계정을 호출하지 않았다.
- 모든 새 도구의 중단 표시 적용과 기존 호출 예산 테스트가 통과했다.
- 실제 기본 작업공간에 생성한 `documents/JARVIS_START_HERE.md` 예제 1개를 인덱싱했다. 결과는 파일 1개·조각 1개·제외 파일 0개였으며, “로컬 벡터 검색” 질의가 해당 문서를 반환했다.
- `pip check`: `No broken requirements found.`
- 인증 도우미의 `--help` 실행을 확인했다. 로그인 브라우저를 열거나 계정 연결을 시도하지 않았다.

## 남은 항목과 한계

- Google Cloud Desktop OAuth 클라이언트 JSON 준비, Gmail·Calendar API 활성화 및 사용자 직접 로그인 후 실계정 검증이 필요하다. 인증 파일을 받기 전까지 실제 수신 메일·일정 브리핑 결과는 확인할 수 없다.
- 현재 검색은 로컬 어휘 특징 벡터이며 신경망 의미 임베딩이 아니다. PDF·DOCX 파싱, 의미 모델 선정·다운로드·외부 임베딩 API는 포함하지 않았다.
- SQLite에 원문 사본이 저장되며 암호화·OS 자격 증명 저장소는 포함하지 않았다. 파일·토큰은 운영자만 접근 가능한 디렉터리에서 관리해야 한다.
- 기존 응용 프로그램 수준 경로 정책의 동시 변경 경쟁 조건, 즉시 중단 미구현 등 OS 격리 과제는 그대로 남아 있다. 제한된 문서 순회도 OS 수준 실행시간·메모리 강제 격리를 제공하지 않는다.
- 현재 채팅에 노출된 자비스 도구 목록은 이전 3개다. 앱 재시작 또는 MCP 재연결 후 새 도구 5개의 로딩을 확인해야 한다. 서버 프로세스를 임의로 종료하거나 Codex 설정을 변경하지 않았다.

사용 안내와 계정 준비 절차는 `docs/guides/knowledge-and-google.md`를 따른다.

## 2026-10-17 — 파일 정리 관련 기능 묶음 초기 구현

- file_organizer.py와 tools/files/ 도구 6개를 추가했다. 프로젝트 미리보기·적용·기록·undo 미리보기·undo와 다운로드 읽기 전용 시뮬레이션이다. 전체 도구는 18개이고 기존 12개를 유지한다.
- 새 요청·Move·Operation 데이터 경계를 엄격한 Pydantic 모델로 검증한다. 기존 MCP 8개 계약 자료는 변경하지 않고 추가된 도구 이름만 기존 목록 검사에 반영했다. Pydantic은 이미 설치된 버전(2.14.1)을 직접 의존성으로 명시했다.
- 모듈 단독 분류·모델 생성 스모크가 통과했다 (명령 실행 0.54초). 영향 범위인 파일 정리·로더·스냅샷·실제 MCP 기본 흐름 테스트 63개가 통과했다 (`63 passed in 5.50s`). Python 기동과 별도 MCP 프로세스 실행을 포함하는 관련 검증이며 전체 테스트를 실행한 결과로 보고하지 않는다. 마지막 전체 검증 99개 기록은 유지한다.
- 임시 프로젝트에서 분류와 사전 백업, 무덮어쓰기 이동, 기록 영속화·재시작 후 undo 미리보기, 재백업·undo를 실제 MCP로 확인했다. source 변경·목적지 충돌·미리보기 만료/재사용·경로/타입 오류·조작된 기록 거부·정리 실패 롤백·롤백 실패 후 차단·undo 실패 롤백·중간 중단·공통 도구 중단 정책도 검증했다.
