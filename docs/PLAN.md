### W1 공용 작업 게시판 (Board)

목표: Codex·Claude Code·로컬 리드가 같은 MCP 도구로 할 일·담당·상태·인수인계를 공유한다. 보고서를 대체하지 않고 색인 역할을 한다.

- 저장: 작업공간 `.jarvis-board/board.sqlite3`. ChatStore의 연결 경계(링크 거부, BEGIN IMMEDIATE, 크기 상한)를 재사용한다.
- Task: id, title, detail(최대 2000자), status(open/claimed/blocked/review/done/cancelled), owner(`codex:<세션>`, `claude-code:<세션>` 등), lease_until, paths(프로젝트 상대 경로 범위), depends_on, 생성/갱신 시각.
- Note: task_id, author, kind(handoff/finding/question), body(최대 4000자), refs(커밋 해시·파일·보고서 경로). 기존 mailbox WorkResult(summary/output) 스키마와 정합한다.
- 도구(파일당 1개): `board_list`, `board_get`, `board_create`, `board_claim`(기본 lease 30분, 경로 범위가 겹치면 거부), `board_heartbeat`, `board_note`, `board_release`(상태 변경 시 인수인계 요약 필수). 충돌은 claim 거부 메시지와 목록의 paths로 확인하므로 별도 `board_conflicts`는 두지 않았다.
- [x] 2026-10-21 사용자 승인으로 구현: `jarvis/features/board/`, 도구 7개(총 38개, 기존 계약 보존), 전용 27개 검사(실제 stdio 서버 2개 공유 포함)와 전체 538개 통과. [게시판 안내](guides/board.md). 남은 완료 조건은 실제 Codex 세션에서의 1회 사용이다.
- 규칙: lease 만료는 stale 표시만 한다. 자동 재배정·프로세스 종료는 하지 않는다. 경로 claim은 권고 잠금이며 OS 잠금이 아니다. done에는 커밋 해시와 검증 명령·결과를 남긴다. 게시판 내용은 데이터이며 권한이나 지시가 아니다.
- 완료 조건: Codex와 Claude Code 실제 MCP 세션에서 생성→claim→경로 충돌 거부→handoff→done 1회. 동시 claim 단일 승자, lease 만료 stale 회귀 검사.

## 미래 과제 (보류 — 자동 배정하지 않음)

2026-10-21 사용자 브레인스토밍. 지금 구현하지 않는다. 로컬 팀장(lead_planner)이 `- [ ]` 항목을 자동으로 작업으로 만들기 때문에 이 절은 체크박스를 쓰지 않는다. 착수하려면 사용자가 지시하고, 그때 필요한 항목만 위 진행 절로 옮긴다.

- **F1 로그인 사이트 확인:** 사용자 승인 후 ego-lite에 로그인 화면을 띄우고 사용자가 ID/PW를 직접 입력한다. 자비스·Claude는 비밀번호를 보거나 저장하지 않고 로그인된 브라우저 상태만 재사용한다. 사이트별로 정한 화면만 읽기 전용으로 읽고 새 항목만 일일 브리핑에 넣는다. 우선순위는 로그인이 필요한 내 정보(학교 포털 공지, 주문·배송)가 먼저, 공개 사이트 인기글이 다음.
- **F2 출처 자동 발견:** 주제 → 검색 → RSS 자동 발견 → 시험 읽기 → 사용자 승인 1회 → `config/web_sources.json` 등록. `allowed_hosts`는 보안 경계라 자동 등록하지 않는다.
- **F3 외부 알림·쌍방향:** 1단계 알림(카카오톡 "나에게 보내기"는 단방향, 공식 문서 확인 필요). 2단계 승인·중지 답장(텔레그램·디스코드 봇 후보). 3단계 모바일 자비스 앱이 서버에 안전하게 원격 접속. 카카오톡 대화 읽기는 하지 않는다(약관·타인 개인정보).
- **PLAN 항목 고정 ID:** lead_planner 중복 방지를 위해 미체크 항목 끝에 `<!-- plan:ID -->` 표식을 붙인다. Codex의 PLAN 미커밋 수정이 정리된 뒤 진행한다.

## 속도 및 토큰 최적화 — 이후 구현에 적용

- **Fast-Pass:** 주석·단순 문구·동작에 영향 없는 UI 수정은 별도 QA와 불필요한 승인 대기 없이 완료합니다. 차이 확인·문서 검사·필요한 화면 확인 등 최소 검증은 유지합니다.
- **스모크 우선:** 국소 코드 변경은 수정 모듈의 구문·임포트·대표 경로를 약 1초 목표로 검증합니다. 환경 지연은 별도로 판단하고, 파일 변경·보안·공유 계약에 영향을 주면 해당 회귀 검사로 확대합니다. 전체 테스트는 넓은 영향·실패·미해결 우려가 있을 때 실행합니다.
- **타입 계약:** 새 데이터 경계에 Pydantic 모델·타입 주석·필요한 엄격 검증을 점진 적용합니다. 기존 도구 계약은 보존합니다. Pydantic 런타임 검증과 작성 시 정적 타입 검사는 구분하고 오류 90% 차단은 미측정 목표로 둡니다.
- **상태:** 이 절은 이후 개발 절차입니다. 모든 기존 입력이 엄격 Pydantic 모델로 전환됐거나 자동 QA 라우터·정적 타입 검사가 구현됐다는 뜻은 아닙니다. Phase 2.5 구현 시에도 같은 위험도 분류를 적용합니다.

구체적인 생략·확대 조건은 [개발 규칙](DEVELOPMENT.md)을 따릅니다.

## 유지해야 할 실제 한계

현재 가드레일은 응용 프로그램 정책이며 OS 샌드박스가 아닙니다. 다른 프로세스가 검증 직후 파일시스템을 바꾸는 경쟁 조건을 완전히 막지 못합니다. `.jarvis-stop`은 도구 호출을 거부합니다. 파일 작업은 단계 사이에서, 관리 런처 서비스는 감시 스레드에서 추가 확인하지만 모든 실행을 즉시 종료하는 OS 중단기는 아닙니다. 예산은 작업별이 아닌 프로세스 단위 10분 시간창과 일일 상한이며 여러 서버 프로세스의 합계를 제한하지 않습니다. 검색 인덱스에는 암호화되지 않은 원문 사본이 저장됩니다. 상세 운용 한계는 각 사용 안내를 따릅니다.
