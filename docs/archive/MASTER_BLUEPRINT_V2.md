# 프로젝트 J.A.R.V.I.S. 고도화 통합 계획서 (Master Blueprint V2)

반영일: 2026-10-17 (Asia/Seoul)

이 문서는 사용자가 제시한 V2 계획을 보존한 향후 설계 기준이다. 로드맵 변경은 아래 본문을 따르며, 기존 개발 지침의 코드 보존·회귀 테스트·오류 은폐 금지·보안 우선·단계별 완료 검증 원칙은 계속 적용한다. 문서 반영은 다음 Phase의 구현 시작 지시가 아니다.

## 1. 프로젝트 비전 및 목표

- 최종 목표: 사용자의 PC 환경을 수족처럼 부리며, 지식(세컨드 브레인)과 음성·시각 인터페이스를 통해 실시간으로 상호작용하는 개인용 슈퍼 AI 에이전트 시스템 구축.
- 아키텍처 철학:
  - 두뇌(Backend): 안전 가드레일이 적용된 FastMCP 기반 파이썬 코어 서버.
  - 몸(Frontend): 3D 시각화, 음성 대화, 화면 공유, 모델 스위칭이 가능한 차세대 웹/데스크톱 HUD 인터페이스.

## 2. 개발 단계별 로드맵 (Phased Roadmap)

### Phase 1 — 코어 백엔드 및 보안 가드레일 구축 (현재 완료 단계)

- 목표: 시스템 제어의 뼈대와 철저한 보안 경계 확립.
- 주요 기능:
  - FastMCP(`server.py`) 코어 서버 구축 및 툴 등록.
  - 안전 가드레일(`guardrails.py`): 화이트리스트 기반 셸 명령어 제어, 엄격한 경로 검증, 20회 호출 예산 제한, `.jarvis-stop` 킬스위치.
  - 실시간 시스템 리소스 모니터링(`psutil`).
  - 타임아웃 방어막이 적용된 안전한 데스크톱 스크린샷 캡처.

### Phase 2 — 지식 연결 및 세컨드 브레인 백엔드 확장 (다음 단계)

- 목표: 사용자의 로컬 파일/폴더 및 개인 정보(이메일, 캘린더 등)를 자비스가 인덱싱하고 검색할 수 있도록 확장.
- 주요 기능:
  - 로컬 문서/노트 벡터화 및 검색 도구 연동.
  - 구글 캘린더/이메일 브리핑 API 연동.

### Phase 3 — 차세대 프론트엔드(몸) 및 인터페이스 구축 (영상 영감 반영)

- 목표: 사용자가 눈으로 보고 귀로 들으며 직관적으로 소통할 수 있는 고도화된 UI/HUD 구축.
- 주요 기능 (영상 핵심 기능 벤치마킹):
  - **3D 세컨드 브레인 인터페이스:** 컴퓨터 속 파일과 폴더 구조를 3D 궤도 오브젝트로 시각화하여 직관적으로 탐색 및 조작.
  - **음성 핸즈프리 인터랙션(STT/TTS):** “Hey Jarvis” 웨이크 워드 감지 및 음성 대화 인터페이스 탑재.
  - **실시간 화면 공유 및 비전(Vision) 모듈:** 사용자가 공유한 특정 브라우저/화면 탭을 자비스가 실시간으로 인지하고 분석.
  - **다중 모델 스위칭 패널:** OpenRouter API 등을 연동하여 대화 중 실시간으로 자비스의 두뇌(모델)를 변경. 예: Claude ↔ Gemini ↔ Groq 등.
  - **모닝 브리핑 시스템:** 매일 아침 일정, 이메일, 주요 투두 리스트를 음성과 카드로 브리핑.

## 3. 프론트엔드(몸) 아키텍처 설계 초안

### 기술 스택 (예정)

- Frontend Framework: React / Next.js + Three.js (3D 파일 궤도 시각화용).
- Communication: WebSocket / MCP Client SDK를 통한 백엔드(`jarvis-core`) 실시간 통신.
- Voice & Vision: Web Speech API / MediaStream API (화면 공유 및 음성 입출력).

### 화면 레이아웃 (HUD 스타일)

- 중앙 뷰: 3D 지식 궤도(Second Brain) 또는 실시간 작업 공간 시각화 영역.
- 하단 컨트롤바: 음성 핸즈프리 활성화 버튼, 화면 공유 버튼, AI 모델 스위칭 드롭다운.
- 우측 사이드바: 실시간 시스템 상태(CPU/RAM) 모니터링 위젯 및 자비스의 대화형 로그 카드.

## 4. 기존 구현과의 연결 및 후속 설계 기준

이 절은 위 사용자 계획을 구현에 연결하기 위한 정리이며, 기술 선정과 연동 완료를 뜻하지 않는다.

- **로드맵 우선순위:** 다음 단계는 V2 Phase 2다. 기존 문서의 Phase 2~4 번호와 순서는 역사적 참고로 남기고, 앞으로의 단계 진행은 V2를 따른다. 기존 계획의 브라우저 자동화·감사 로그·다중 에이전트 등 V2에 명시되지 않은 기능은 삭제하지 않되 별도 범위 합의 전까지 자동 구현하지 않는다.
- **현재 구현의 실제 제한:** 호출 예산은 프로세스 전체 20회이며 `.jarvis-stop`은 다음 호출을 차단한다. 진행 중인 작업을 즉시 취소하지 않는다. 명령·경로 검증은 응용 프로그램 수준 정책이며 OS 수준 샌드박스가 아니다. 구체적인 검증 결과와 제한은 `PHASE1_VERIFICATION.md`를 따른다.
- **기존 보안 보강 항목 유지:** OS 격리, 실행 중 취소, 자원 제한과 즉시 중단 요구는 후속 설계 과제로 유지한다. 새로운 파일 접근·실행 경로를 추가하기 전에 해당 경계가 충분한지 검토한다.
- **로컬 지식 접근:** PC 전체 접근을 자동 허용하지 않는다. 초기 대상은 기존 `JarvisWorkspace` 안으로 한정하고, 외부 폴더가 필요하면 사용자가 지정한 범위와 권한 정책부터 설계한다. 문서 내용은 지시가 아닌 신뢰하지 않는 데이터로 처리한다.
- **개인 정보 연동:** 현재 Codex에 연결된 이메일·캘린더 도구와 독립 J.A.R.V.I.S. 서버의 API 인증은 구분한다. 연결된 계정의 권한이나 토큰이 서버에 자동 전달된다고 가정하지 않는다. 초기 브리핑은 읽기 중심으로 설계하고 발송·일정 변경은 별도 요청 범위로 다룬다.
- **벡터화 및 모델 제공자:** 임베딩 모델, 저장소, 제공자 및 비용은 아직 확정하지 않았다. 로컬 처리와 외부 전송 범위를 비교한 뒤 선택하며, 개인 문서·이메일을 외부 서비스에 자동 전송하지 않는다.
- **프론트엔드 통신:** 현재 서버는 stdio MCP다. 웹 HUD용 통신 계층은 별도 설계가 필요하며, 단순히 브라우저에 로컬 실행 권한이나 API 비밀키를 노출하지 않는다. 계획서에 기재된 웹 기술의 실제 지원 범위는 구현 시 검증한다.
- **영상 및 기술 후보:** 영상 원본은 이 요청에 포함되지 않았으므로 기술된 기능만 참고한다. OpenRouter, 개별 모델, 음성 API 등의 사용 가능 여부와 구체적인 제품·모델 구분은 구현 시 공식 자료로 확인한다.
- **자동화:** 모닝 브리핑은 목표 기능이다. 이 문서 저장만으로 예약 실행, 마이크 상시 수집, 화면 상시 공유를 활성화하지 않는다.
- **단계별 진행:** V2 Phase 2 착수 지시를 받으면 먼저 인덱싱 대상·저장 정책·인증 방식·검증 기준을 구체화한다. 작은 단위로 구현하고 기존 도구 회귀 검증을 수행한다. Phase 3는 별도 진행 지시 후 시작한다.
