# 프로젝트 J.A.R.V.I.S. 고도화 통합 계획서 (Master Blueprint V3 - Token Optimized)

반영일: 2026-10-17 (Asia/Seoul)

사용자가 제시한 다음 설계용 참조안이다. 아래 1~2절은 사용자 계획을 보존하며, 3절은 기존 구현에 적용할 때의 기준이다. 이 문서의 저장은 코드 이전·리팩터링·신규 도구 구현 지시가 아니다.

## 1. 프로젝트 비전 및 목표

- 최종 목표: 사용자의 PC 환경을 수족처럼 부리며, 지식(세컨드 브레인)과 음성·시각 인터페이스를 통해 실시간으로 상호작용하는 개인용 슈퍼 AI 에이전트 시스템 구축.
- 아키텍처 철학:
  - 두뇌(Backend): 안전 가드레일이 적용된 FastMCP 기반 모듈형/플러그인 파이썬 코어 서버.
  - 몸(Frontend): 3D 시각화, 음성 대화, 화면 공유, 모델 스위칭이 가능한 차세대 웹/데스크톱 HUD 인터페이스.
  - 최적화 원칙: 토큰 소모 최소화, 도구 단위(Tool-per-File)의 극단적 격리, 100% 안전 가드레일 통제.

## 2. 토큰 절약형 아키텍처 및 디렉토리 구조 (Token-Saving Plugin Architecture)

새로운 도구 추가나 코드 수정 시 전체 프로젝트 대신 해당 도구 파일을 중심으로 전달하여 토큰을 90% 이상 절약하는 구조를 목표로 한다.

```text
JarvisWorkspace/
├── .venv/                      # 가상환경
├── requirements.txt            # 의존성 패키지 목록
├── AGENTS_CONTEXT.md           # [토큰 절약] 프로젝트 전체 구조 및 현재 진행 상황 (50줄 요약 지도)
├── server.py                   # [메인] 툴 자동 로드만 수행하는 경량화된 실행 파일 (수정 거의 없음)
├── guardrails.py               # [보안] 화이트리스트, 20회 예산, .jarvis-stop 킬스위치
│
└── tools/                      # 독립 플러그인 폴더 (도구 1개당 파일 1개)
    ├── __init__.py             # tools 폴더 내부 툴 자동 바인딩 (Auto-loader)
    ├── shell_tool.py           # [Phase 1] 셸 제어 도구 (독립)
    ├── system_tool.py          # [Phase 1] 시스템 리소스 & 스크린샷 도구 (독립)
    ├── search_tool.py          # [Phase 2] 웹 탐색 & 깃헙 클론 도구 (독립)
    └── brain_tool.py           # [Phase 2] 로컬 문서 벡터화 & 세컨드 브레인 탐색 도구 (독립)
```

## 3. 다음 설계 시 적용 기준

- **문서 우선순위:** V3는 모듈화·플러그인 구조의 최신 설계 참조다. V3에 전체 단계 로드맵이 다시 정의되지 않았으므로 단계 진행은 V2를 유지한다. 기존 개발 지침의 코드 보존·회귀 테스트·오류 은폐 금지·보안 우선 원칙도 유지한다.
- **현재 상태:** 기존 서버에는 시스템 도구 3개와 지식·브리핑 도구 5개가 있다. 로컬 검색은 구현·검증했고 Google 실계정 연결은 대기 중이다. 실제 파일 구조와 검증 결과는 `AGENTS_CONTEXT.md`, `PHASE1_VERIFICATION.md`, `PHASE2_VERIFICATION.md`를 따른다.
- **실행 코드와 문서 작업공간 분리:** 위 트리는 사용자 설계 예시다. 현재 코드는 프로젝트 루트에 있고 `JarvisWorkspace`는 도구가 접근하는 데이터 영역이다. 다음 설계에서도 실행 코드·가상환경·인증정보·플러그인을 검색·쓰기 가능한 문서 작업공간과 분리한다. 실제 디렉터리를 옮기려면 Codex 등록 경로와 회귀 검증을 함께 갱신한다. 이번에는 파일을 옮기지 않는다.
- **도구 단위 분리:** 실제 리팩터링에서는 MCP 도구 하나당 파일 하나를 기본으로 한다. 예시의 `system_tool.py`는 상태 조회와 캡처를 함께 담지만, 구현 시에는 각각 분리한다. `brain_tool.py`의 인덱싱·검색·삭제도 각각 분리하고 공통 저장소·인증·검증 코드는 공유 서비스로 유지한다.
- **공통 검증 경계:** 서버 전체의 단일 가드레일·예산·중단 상태를 모든 도구가 공유하게 한다. 새 플러그인이 이를 우회해 직접 등록·실행하지 못하도록 등록 인터페이스와 호출 경계를 설계한다. 도구 파일을 분리하는 것 자체가 보안 격리는 아니다.
- **자동 로더 신뢰 범위:** 운영자가 관리하는 코드 디렉터리의 검증된 플러그인만 로드한다. 문서 작업공간이나 다운로드한 저장소에서 Python 파일을 찾아 자동 실행하지 않는다. 중복 도구 이름·잘못된 등록 규약·임포트 오류는 숨기지 않고 시작 실패로 처리한다. 경로·명령 검증만으로 Python 플러그인 자체의 임의 동작을 격리할 수는 없다.
- **요약 지도:** `AGENTS_CONTEXT.md`를 50줄 이내로 유지해 구조·현재 상태·공통 계약·검증 방법을 전달한다. 변경 대상 파일부터 읽되 공유 계약·의존성·관련 테스트가 영향을 받으면 해당 파일도 확인한다. 파일 하나만 읽는 것을 절대 규칙으로 삼지 않는다.
- **웹 탐색·GitHub 복제:** V3 트리에 제시된 신규 후보 기능이다. V2 Phase 2의 로컬 검색이나 기존 셸 허용 목록에 이미 포함된 것으로 간주하지 않는다. 구현 착수 시 별도 범위를 정하고 도메인·외부 전송·복제 목적지·크기·시간 제한을 설계한다. 복제한 코드는 자동 설치·실행하지 않는다.
- **측정과 보장 구분:** 토큰 90% 이상 절약은 목표이며 아직 측정하지 않았다. 100% 가드레일 통제는 모든 도구에 공통 검증을 적용한다는 설계 목표다. 무결점 보안 보장으로 표현하지 않으며 기존 OS 격리·동시 변경 경쟁 조건·실행 중 즉시 중단의 한계는 계속 추적한다.
- **이전 완료 기준:** 도구 이름·입력·출력·오류 동작을 보존하고 기존 테스트를 통과해야 한다. 새 도구 등록에도 공통 검증이 적용되는지 확인하며, 이후 도구 추가 시 `server.py` 수정 없이 등록되는지 검증한다. 사용자 지시 전까지 이번 구조 개편을 시작하지 않는다.
