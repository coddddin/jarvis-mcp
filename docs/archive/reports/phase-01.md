# Phase 1 완료 검증

[문서 안내](../../README.md) · [현재 계획·상태](../../PLAN.md)

이 보고서는 검증 당시의 기록입니다. 현재 상태와 다음 작업은 통합 계획을 따릅니다.

검증일: 2026-10-17 (Asia/Seoul)

## 적용 범위

사용자의 최신 Phase 1 요청을 기준으로 FastMCP 서버, 안전 검증기와 MCP 도구 3개를 구현했다. 기존 마스터 계획에서 Phase 2에 배치했던 도구를 이번 요청에 따라 Phase 1에 포함했다. 후속 브라우저·메모리·HUD·다중 에이전트 구현은 시작하지 않았다.

작업 시작 시 기존 구현·테스트는 없었으며, 기존 개발 지침과 프로젝트 지침을 유지했다. `sources/` 및 동기화 자료는 수정하지 않았다.

## 결과

- `server.py`: stdio MCP 서버와 `run_safe_shell_command`, `get_system_status`, `take_screenshot` 구현.
- `guardrails.py`: 명령 허용·차단 정책, 작업공간 경로 제한, 링크·정션 차단, 호출 예산, 중단 표시 확인 구현.
- `tests/test_phase1.py`: 34개 테스트 통과. 마지막 실행 결과 `34 passed in 1.62s`.
- 실제 MCP 클라이언트로 서버 시작, 초기 연결, 도구 목록 조회, 허용 명령 실행, CPU·메모리·디스크 조회 및 오류 응답을 확인했다.
- Windows 정션을 통한 외부 디렉터리 접근과 비존재 파일 경로 우회를 차단했다.
- 캡처 가상 입력으로 PNG 저장과 오류 전달을 검증했다. 실제 데스크톱도 2560×1440 PNG로 기본 작업공간에 저장하고 PNG 무결성을 확인했다. 캡처 이미지는 자동 외부 전송하지 않았다.
- 실제 캡처 검증 중 제한된 실행 환경에서 화면 API가 지연됐다. 캡처를 별도 프로세스로 옮기고 10초 시간 제한을 적용한 뒤 실제 화면 접근 권한이 있는 환경에서 성공했다. 시간 초과 오류 전달도 자동 테스트에 포함했다.
- `pip check`: `No broken requirements found.`
- Python 3.13.1 / Windows에서 실행했다. 직접 의존성은 `requirements.txt`, 테스트 의존성은 `requirements-dev.txt`, 검증 환경의 전체 패키지 버전은 `requirements-lock.txt`에 기록했다.

## 운용 제한

- 명령 도구는 문서화된 읽기 전용 명령 5종만 제공한다. 임의 셸·스크립트·파일 삭제·수정·네트워크 명령은 허용하지 않는다.
- 경로 정책은 운영체제 수준 샌드박스가 아니다. 신뢰하지 않는 로컬 프로세스가 파일시스템을 동시에 변경하는 공격은 별도 OS 격리가 필요하다.
- 호출 한도는 작업별이 아닌 더 엄격한 서버 프로세스 전체 20회이며, 중단 파일은 다음 호출부터 적용된다. 이미 진행 중인 작업을 즉시 취소하는 전역 중단기는 구현하지 않았다.
- 스크린샷은 접근 가능한 데스크톱이 필요하며 민감정보가 포함될 수 있다. 검증용 PNG를 포함해 작업공간 산출물은 운영자가 관리한다.
- 토큰 예산은 모델 호출 계층이 도입될 때 구현할 항목이다. 현재는 모델 호출을 수행하지 않는다.

요청한 Phase 1 범위는 구현과 검증을 완료했다. 위 제한은 전체 설계의 고급 격리·즉시 중단 기능을 완료했다는 의미로 해석해서는 안 된다. 다음 Phase는 사용자 지시를 받은 뒤 시작한다.


## 2026-10-17 — V4 플러그인 구조 정비

- 변경 전 전체 테스트 58개 통과 (`58 passed in 2.16s`). 기존 도구 계약을 tests/fixtures/tool_contract.json에 기록했다.
- server.py는 서버 생성·로딩·실행 진입점으로 축소했고 runtime.py에 설정·공유 서비스·의무 호출 경계를 배치했다.
- 기존 8개 도구를 tools 아래 파일 8개로 분리했다. 도구 이름·설명·입력 스키마 등 계약 비교가 통과했으며 셸·상태·캡처·지식·Google 오류 처리를 보존했다.
- 자동 로더는 코드 영역의 *_tool.py만 대상으로 한다. 신규 파일 등록에 서버 본문 수정이 필요하지 않음을 테스트했다. 중복·잘못된 등록 함수·잘못된 반환·비동기 함수·임포트 오류·하드링크·데이터 영역 로딩을 거부했다.
- 서로 다른 새 도구 사이에도 20회 예산을 공유하고 중단 시 도구 본문에 진입하지 않음을 검증했다. 예상하지 못한 예외가 가짜 성공이나 민감 상세로 전달되지 않음을 확인했다.
- 전체 테스트 71개 통과 (`71 passed in 2.31s`). 실제 stdio MCP 클라이언트로 기존 도구 목록·셸·상태·문서 검색과 인증 미설정 오류도 확인했다. 캡처는 모의 이미지와 오류 경로로 회귀 검증했으며 이번에 실제 화면을 추가 캡처하지 않았다.
- 코드·가상환경·작업공간·인증·Codex 등록 경로는 유지했다. 데이터나 동기화 원본을 이동·수정하지 않았다. Google 실제 인증과 V4 신규 도구는 별도 미완료 상태다.
- 플러그인은 신뢰된 운영자 Python 코드다. 호출 경계는 임포트 부작용을 격리하지 않으며 OS 샌드박스·즉시 중단 한계는 유지된다. 실행 중 핫 리로드는 없고 재연결 후 새 구조를 사용한다.
- 운영과 신규 도구 계약은 [플러그인 안내](../../guides/plugins.md)를 따른다.


## 2026-10-17 — 계열별 도구 디렉터리 정리

- 기존 12개 도구를 tools/system(3), knowledge(3), google(2), snapshots(4)로 이동했다. 서버 진입점·서비스·데이터·등록 경로는 유지했다.
- 로더는 루트 호환 파일과 계열 한 단계의 도구를 발견하며 모듈명에 계열을 포함한다. MCP 이름은 계열과 무관하게 중복을 거부한다. 링크·정션 계열을 임포트 전에 차단하고 계열 초기화 코드는 자동 실행하지 않는다.
- 같은 파일명의 서로 다른 계열, 계열 간 중복 MCP 이름, 정션 계열 거부 테스트를 추가했다. 기존 파일 경로를 참조한 테스트는 새 임포트 경로로 갱신했다.
- Fast-Pass/스모크 우선 정책에 따라 로더·계약·공통 경계, 이동된 시스템 도구, 실제 MCP 기본 흐름·스냅샷 흐름만 선택했다. 관련 테스트 20개 통과 (`20 passed in 2.94s`). 전체 테스트를 다시 실행한 것으로 보고하지 않는다. 이전 전체 검증은 Phase 2의 99개 기록을 유지한다.
- 신규 도구는 해당 계열로 추가하고 같은 계열 폴더를 우선 재사용한다. 예정 분류는 files/development/workflows/web이며 이번에는 미구현 파일·빈 폴더를 추가하지 않았다.
- 문서 분류·실행 계약과 프로젝트 지도를 갱신했다. [플러그인 안내](../../guides/plugins.md)를 따른다.
