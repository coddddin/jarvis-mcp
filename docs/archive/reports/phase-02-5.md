## 2026-10-18 — 자율 진행 묶음: 기능 QA·예산·기억·이벤트·실격리

- 사용자가 토큰 한도까지 계획서에 따라 자율 진행하도록 지시했다. 먼저 제한된 정수 AST 해석 QA와 영속 모델 예약을 연결했다. 무한루프/호출/속성/기본 인자/외부 이름/큰 정수 등을 해석기에서 거부하며 Python exec/eval을 사용하지 않는다. 등록 사례/모드/제안 해시와 증거가 다르면 완료 이력을 거부한다.
- 요청당 출력 1,024+컨텍스트 8,192의 보수적 예약, 기본 출력 8,192/합산 65,536 한도, 실패 호출 환불 금지와 기존 역할·시간·수정 한도를 결합했다. 실제 tokenizer 청구량·유료 외부 API 비용 제어와 구분한다. 재시작/새 실행 객체로 동일 작업의 예산을 초기화하지 않는다.
- 기억은 owner/project 범위, 종류/키/출처/시각/revision/확인 여부를 가진 로컬 SQLite 별도 테이블로 구현했다. 수정 시 확인 해제, 오래된 revision 거부, 최대 1,000개/값 1,000자/보존 1~365일, 인식된 비밀값 거부를 적용했다. opt-in 작업에만 확인된 최대 8개를 신뢰되지 않은 선호 데이터로 전달한다. source=synthetic_setup_demo/owner=verification의 데모 기억으로 검증했으며 사용자 실제 선호를 임의로 추정해 등록하지 않았다.
