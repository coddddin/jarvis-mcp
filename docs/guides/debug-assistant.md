# 에러 분석·수정 제안 — 읽기 전용 초기 버전

[문서 안내](../README.md) · [현재 계획](../PLAN.md)

## 사용하기

자비스 서버를 재연결한 뒤 `analyze_error_log(error_log="", log_path="", code_path="")`를 사용합니다. 서버의 도구는 현재 합계 27개입니다. 도구 하나를 `jarvis/features/development/tools/debug_assistant_tool.py`에 두고 공통 서비스는 `jarvis/features/development/service.py`에서 제공합니다.

- “자비스로 이 로그 분석해줘: `ModuleNotFoundError: No module named 'requests'`”처럼 로그 텍스트만 전달할 수 있습니다.
- 작업공간의 로그는 `log_path="projects/demo/error.log"`로 지정합니다. error_log와 log_path를 동시에 지정할 수 없습니다.
- Python 문법 점검은 `code_path="projects/demo/app.py"`로 지정합니다. 로그 없이 소스만 점검해도 됩니다.
- 로그와 선택한 소스의 관계는 사용자가 지정합니다. traceback에 적힌 경로를 자동으로 읽거나 모듈을 import하지 않습니다.

파일 경로는 **JarvisWorkspace/projects/<프로젝트명>/ 내부**만 지원합니다. 로그는 UTF-8 `.log`·`.txt`, 코드는 UTF-8 `.py`입니다. 서버 운영 코드·외부 프로젝트·다운로드를 이 도구로 직접 읽도록 경로 정책을 확대하지 않습니다. 숨김·인증·제외 파일, 링크·정션·하드링크와 외부 경로는 기존 가드레일·스냅샷 읽기 정책으로 거부합니다.

## 결과와 한계

- `findings`: 파서가 확인한 문법 오류 또는 로그 패턴에서 찾은 원인 후보입니다. `basis=parser`와 `basis=log_pattern`을 구분합니다. line은 선택한 소스의 오류 줄이며 로그의 임의 줄 번호를 소스 증거로 간주하지 않습니다.
- `log_excerpt`: 정제한 로그의 마지막 40줄, 최대 4000자입니다. 입력 로그는 최대 65,536자, 파일별 읽기는 최대 65,536바이트, 소스는 최대 2000줄·줄당 4000자입니다. 한도를 넘으면 불완전한 분석을 성공으로 반환하지 않습니다.
- `proposed_diff`: CPython이 `expected ':'`로 보고한 단일 누락 콜론에 한해 후보를 만듭니다. 문자열 속 #와 실제 주석을 토큰으로 구분하고 변경 후 AST 파싱과 컴파일이 모두 성공할 때만 diff를 반환합니다. 다른 문법 오류가 남아 있으면 diff를 제공하지 않습니다. source에 인식 가능한 비밀값이 있으면 diff를 억제합니다.
- 문법 점검은 AST 파싱과 코드 객체 컴파일까지만 수행합니다. exec/eval·import·프로세스 실행·패키지 설치·수정 적용·네트워크·로그 자동 저장은 수행하지 않습니다. 문법 성공은 실행 성공이나 로그 오류 해결 보장이 아닙니다. 별도 프로세스의 CPU/메모리 하드 격리는 아직 없습니다.
- 알려진 Python 예외 15종의 조치 안내를 규칙으로 반환합니다. 모델이나 의미 추론 엔진을 사용하지 않으며, 패턴이 없으면 미분석 사실을 알립니다. 명령을 포함한 로그도 신뢰하지 않는 데이터로 표시하고 실행하지 않습니다.
- 비밀번호·secret/token/credential·API 키·Authorization/Cookie 할당 줄, 알려진 토큰 형식, 개인키 블록·URL 인증값 등을 정제합니다. **모든 비밀 형식을 탐지하는 보장은 없습니다.** 로그를 붙여넣기 전에 민감값을 직접 제거하세요. 가림은 이 도구의 반환값에 적용되며 사용자가 이미 채팅에 보낸 내용을 지우지 않습니다. 원문을 외부 모델로 자동 전송하지 않습니다.

## 적용 권한과 다음 범위

이 도구는 원본을 변경하지 않으므로 미리보기 ID나 적용 도구를 제공하지 않습니다. 수정안을 실제 적용하는 기능은 파일 범위·현재 원본 식별·사전 백업·검증 및 실패 복구를 별도 구현한 뒤 제공합니다. 일반 자동 코드 수정·AI 모델 연동·여러 언어 분석·테스트 실행·웹 정보 수집은 이번 범위가 아닙니다.

공통 시간창 호출 예산([시스템 도구](system-tools.md))과 `.jarvis-stop`은 그대로 적용합니다. 새로운 도구를 등록하려면 Codex/Claude에서 자비스 연결을 다시 시작해야 합니다. 실행 중 자동 재로딩은 없습니다.

## 검증

모듈 스모크와 에러 분석·플러그인·Phase 1 관련 검사 73개를 통과했습니다. 실제 stdio MCP 초기화·25개 도구 목록·새 도구 호출과 기존 시스템·문서 검색을 함께 확인했습니다. 실제 사용자 로그·코드를 개발 테스트에서 읽거나 변경하지 않았으며 전체 검사 결과로 보고하지 않습니다. 자세한 이력은 [Phase 2 보고서](../reports/phase-02.md)를 따릅니다.
