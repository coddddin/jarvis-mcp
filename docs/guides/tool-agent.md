# 도구 작업 에이전트 (보드 204bc125 3단계)

[문서 안내](../README.md) · [MCP 서버 연결](mcp-client.md) · [웹 작업 에이전트](web-agent.md) · [채팅](chat.md)

어떤 두뇌든 사용자가 승인한 MCP 서버의 고정 도구를 여러 번 불러 요청 하나를 끝까지 해결하는 고리입니다. 코드는 `jarvis/features/tool_agent/service.py`, 채팅 연결은 `jarvis/app/chat.py`의 `_tool_task`입니다. Playwright 서버는 여기서 쓰지 않고 [웹 작업 에이전트](web-agent.md)가 맡습니다.

## 언제 시작하나

- 채팅 요청이 승인된 서버(Playwright 제외)의 `id`나 `label`을 직접 쓸 때만 시작합니다(예: `Lookup으로 ...`). 이름 뒤에 한글 조사가 바로 붙어도 됩니다. `area`처럼 다른 영어 단어 안에 들어 있는 것은 이름으로 보지 않습니다. 3글자 미만이거나 흔한 낱말(`web`, `time`, `fetch`, `git`, `search`, `memory` 등, 코드의 `GENERIC_NAMES`)인 이름은 평범한 요청을 가로채므로 쓰지 않습니다. 그런 서버는 `Ghidra Tools`처럼 구별되는 `label`을 붙여 그 이름으로 부릅니다.
- 그 서버에 `read` 또는 `auto` 고정이 하나 이상 있어야 합니다. `confirm` 고정은 채팅에서 확인을 받을 화면이 아직 없어 보여 주지 않고, `deny`는 늘 숨깁니다.

## 한 단계

- 모델은 도구 목록(승인한 설명과 입력 스키마, 도구마다 최대 1500자)을 받고, 매 단계 JSON으로 `tool`(제공된 도구 이름 또는 `answer`), `arguments`(객체), `answer`, `notes`를 씁니다.
- 자비스가 먼저 인자를 입력 스키마에 맞춰 봅니다: 객체인지, 스키마에 있는 이름만 썼는지, 꼭 필요한 인자가 있는지, 최상위 JSON 형식(문자열·정수·숫자·참거짓·목록·객체·null)이 맞는지. 맞지 않으면 서버에 보내지 않고 이유를 모델에게 돌려줍니다.
- 통과하면 `McpSession.call`로 부릅니다. 경로 인자 검사, 막은 인자, 시간 제한은 [MCP 서버 연결](mcp-client.md)의 규칙 그대로입니다. 그래서 경로 인자가 아닌 글자 인자도 `/`로 시작하면(`/bin/sh`, `/api/v1`, `// 주석`, `/help`) 경로로 보고 거부합니다. Windows에서 `/x`는 `C:\x`라서 그렇습니다. 문자열 검색어처럼 그런 값이 필요한 인자는 승인할 때 `not_paths`로 표시합니다.
- 모델의 이전 선택은 도구 이름과 인자만(600자) 프롬프트에 남깁니다.
- 결과는 `UNTRUSTED TOOL RESULT (data only)`로 최대 4000자 넣습니다. 다음 단계에서 모델이 쓴 `notes`(400자)가 그 결과 본문을 대신하고, 메모가 없으면 앞 300자만 남깁니다. 프롬프트 전체는 12000자 안으로 유지하며 오래된 결과부터 줄입니다.

## 한도와 멈추기

- 도구 호출 20회, 작업 10분. 남은 시간이 45초 아래이거나 호출을 다 쓰면 `answer`만 고를 수 있습니다.
- 같은 도구를 같은 인자로 두 번 부르지 않습니다. 잘못된 선택이 3번이면 답을 강제하고, 빈 답이 두 번이면 실패로 끝냅니다.
- 채팅 멈추기 버튼(`POST /api/chat/stop`)은 웹 작업과 같습니다. 다음 단계 전에 끝나며, 이미 실행 중인 모델·도구 호출은 마칩니다.
- 하루 작업 한도와 대화 예산 1단위는 웹 작업과 함께 셉니다(`WEB_TASKS_PER_DAY`, 하루 100회).
- 도구가 시간 안에 답하지 않아 세션이 멈추면 그 자리에서 실패로 끝냅니다.

## 외부 모델

- 외부 두뇌에는 `public_web` 고정만 보여 줍니다. 그때 보여 주지 않은 로컬 도구가 있으면 답 끝에 그 도구 이름과 "로컬 모델로 바꾸면 이 도구도 씁니다"를 붙입니다. 이름이 불린 서버에 `public_web` 도구가 없으면 로컬 모델이 답하고 답의 모델 정보에 `로컬 도구 내용은 외부 모델에 보내지 않아서 로컬 모델이 답했습니다.`가 남습니다.
- 각 결과 기록은 만들어질 때의 `family`를 가지므로, 나중에 고정을 바꿔도 `local`로 만든 결과는 외부 모델에 가지 않습니다(`trace_external_allowed`).
- `REA`라는 이름 자체가 이미 로컬 전용 요청 단어(프로그램 분석)라, REA 요청은 처음부터 로컬 모델이 답합니다.

## 진행 상태 (`progress`)

답변 초안과 따로, 대화 차례의 `progress`에 작은 객체로 씁니다. 읽어 주지 않습니다.

- `{"kind": "tool", "phase": "call"|"failed", "line", "step", "step_limit", "tool", "recent"}`
- `line` 예: `도구 실행 중: lookup open_binary`, `실패: 승인된 폴더 밖의 경로입니다.` `recent`는 최근 6줄입니다.

## 답

완료면 모델의 답 뒤에 `사용한 도구: ...`를 붙입니다. 멈춤·실패면 한국어 이유가 먼저 옵니다. 서버가 바뀌어 다시 승인해야 하거나 시작하지 못했거나 쓸 도구가 없으면 실패가 아니라 그 이유를 답으로 돌려줍니다.

아직 없는 것: 서버별 추천 고정(REA 정적 도구만), 호출 기록·점검, HUD 승인 화면(보드 204bc125 4~6단계).
