# 자비스의 제2의 두뇌 — Obsidian 사용법

[문서 목차](../README.md) · [대화 사용법](chat.md) · [기억 저장/확인](agent-controls.md)

Obsidian에는 **다음 작업에서도 다시 쓸 사실·결정·절차와 그 근거**를 남깁니다. 모든 채팅·로그를 복사하는 곳으로 쓰지 않습니다. 사람은 노트를 정리하고, 자비스는 허용된 노트를 색인·검색해 출처와 함께 답합니다. 현재는 노트 쓰기·자동 요약 저장·자동 승인이 연결돼 있지 않아 아래 기록/검토는 직접 수행합니다.

## 1. 올바른 Vault 열기

1. 실제 자비스 서버가 사용하는 작업공간을 먼저 확인합니다. 기본 Vault는 그 안의 `JARVIS-Vault`입니다. 실행 중인 검증 HUD와 평소 MCP 서버의 작업공간은 다를 수 있습니다. 자비스에게 작업공간 경로를 읽기 전용으로 확인해 달라고 요청하고, 파일·노트를 만들기 전에 그 경로를 확인합니다.
2. Obsidian의 보관함 선택 화면에서 **Open folder as vault / 폴더를 보관함으로 열기**로 그 폴더를 엽니다. 폴더가 없으면 확인된 작업공간 안에 빈 `JARVIS-Vault`를 직접 만듭니다. 기존 개인 Vault를 통째로 옮기거나 외부 경로로 정션을 만들지 않습니다.
3. 첫 사용은 노트 한 개로 시작합니다. 플러그인·Sync·자동화는 필수가 아닙니다. 저장소 `docs/`는 개발 문서 원본으로 유지하고 개인 Vault와 동일한 내용을 두 벌 관리하지 않습니다.

Obsidian 공식 안내: [보관함 열기](https://obsidian.md/help/Files%2Band%2Bfolders/Manage%2Bvaults), [속성](https://obsidian.md/help/properties). 아래 메타데이터는 **자비스의 제한된 형식**이므로 Obsidian이 지원하는 모든 속성 형식을 사용할 수 있는 것은 아닙니다.

## 2. 무엇을 어디에 남기나

- `00-Inbox`: 아직 정리하지 않은 관찰·지식 초안. 기본 `review_status: proposed`.
- `10-Knowledge`: 반복 사용할 사용법·사실. 검토한 것만 approved.
- `20-Projects`: 프로젝트별 배경·목표·원본 작업/PR 링크와 재개에 필요한 요약.
- `30-Decisions`: 선택한 안·이유·포기한 안·재검토 조건과 근거.
- `40-Memory`: 다시 확인한 선호·맥락의 노트. 여기 넣었다고 MemoryStore에 자동 반영되지는 않습니다.
- `50-Reviews`: 검증 조건·커밋·결과·미검증 범위. 검사 숫자만 복사하지 않습니다.
- `90-Archive`: 과거 자료. **폴더 이름만으로 검색에서 제외되지 않습니다.** 더 이상 재사용하면 안 되는 노트는 승인 상태도 철회합니다.

처음부터 모든 폴더를 만들 필요는 없습니다. 진행 중 담당/claim은 Board, 원문 대화는 ChatStore, 작업 결과·검증은 PR/장부에 남깁니다. Vault에는 그중 다음에도 쓸 지식과 원본 링크를 남깁니다.

## 3. 작업 결과 한 건을 노트로 만들기

예를 들어 `00-Inbox/jarvis-voice-tab-return.md`를 만들고 아래 내용을 **소스 모드의 일반 Markdown**으로 붙여 넣습니다. 예시 날짜·출처·본문을 실제 값으로 바꾸고 ID는 새 노트마다 고유하게 지정합니다. 이 예시는 알려진 미해결 사례이므로 그대로 approved로 바꾸지 않습니다.

```markdown
---
id: "jarvis-voice-tab-return-20261027"
title: "음성 입력: 탭 복귀 시 버튼 비활성화 관찰"
created: "2026-10-27T09:00:00+09:00"
updated: "2026-10-27T09:00:00+09:00"
source: "https://github.com/coddddin/jarvis-mcp/pull/54"
tags: ["jarvis", "음성", "관찰"]
sensitivity: "private"
review_status: "proposed"
---
# 요약
탭을 숨겼다가 복귀한 뒤 음성 버튼이 비활성화된 채 남는 현상을 모의 환경에서 관찰했다.

## 근거와 범위
- 대상 커밋: 39150c1. 모의 SpeechRecognition 검사에서 재현.
- 실제 Windows 마이크와 사용자 연결 성공은 이 기록의 검증 범위가 아니다.

## 결정·다음 확인
- visibility 복귀 때 버튼 상태 동기화를 확인한다. 수정 완료로 기록하지 않는다.
- 관련 작업/결과: 원본 PR 및 해당 Board 작업 ID를 여기에 기록한다.
```

`task_id`, `commit`, `confidence`, `related` 같은 추가 정보를 넣으려면 지금은 **본문에** 적습니다. 현재 frontmatter에 미등록 필드를 추가하면 자비스가 해당 노트를 거부합니다. 토큰·비밀번호·개인 대화 전문은 넣지 않습니다. 사람이 노트 사이에 링크를 넣을 수 있지만 자비스는 그 링크를 자동 순회하지 않습니다.

## 4. 검토한 노트만 검색에 연결하기

1. 원본과 대조해 사실/추정/미해결을 구분하고 출처를 남깁니다. 아직 수정되지 않은 오류를 완료된 해결책으로 적지 않습니다.
2. 내용과 검색 허용 범위를 확인한 노트만 `review_status: approved`로 변경하고 `updated`를 실제 수정 시각(시간대 포함)으로 갱신합니다. `private`는 무조건 비공개라는 보장이 아니라 메타데이터이며 approved/private도 허용된 로컬 검색에 포함됩니다. `secret`은 제외됩니다.
3. 자비스 MCP가 연결된 클라이언트에서 **“JARVIS-Vault의 승인된 노트를 색인하고, 색인된 수와 제외 사유를 알려줘”**라고 요청합니다. 도구 호출은 `index_obsidian_vault(directory="JARVIS-Vault")`입니다. Obsidian 안의 대화 기능이나 HUD 채팅만으로 색인이 실행되는 것은 아닙니다.
4. **“승인 노트에서 음성 입력 탭 복귀 문제를 찾아줘. 원본 경로와 근거 줄도 보여줘”**라고 요청합니다. `search_obsidian_vault(query="음성 입력 탭 복귀", limit=5)` 결과에서 제목·원본 경로·줄·해시를 확인합니다.
5. 로컬 자비스 채팅에서는 **“내 노트에서 음성 입력 탭 복귀 문제의 확인된 사실과 남은 검증을 알려줘”**처럼 묻습니다. 노트 검색이 연결된 실행본이어야 하며, 현재 띄운 옛 검증본이 최신 코드와 같다고 가정하지 않습니다.

외부 AI 클라이언트에서 MCP를 부르면 결과가 그 클라이언트로 반환됩니다. 로컬 검색 도구 자체의 비전송과 이후 클라이언트의 모델 전송은 다른 경계입니다. 개인 자료를 모든 직원에게 공유하는 기능은 아직 완성되지 않았습니다.

## 5. 다음 세션에서 이어 쓰고, 수정·철회하기

- 새 대화/새 AI 세션에서는 먼저 프로젝트 이름과 질문으로 검색하고 원본 ID·출처·미해결 항목을 확인합니다. “지난번 대화 기억해?”만으로 이 Vault가 자동 조회되는 것은 아닙니다.
- **수정:** 같은 노트의 ID를 유지하고 본문·updated를 수정한 뒤 다시 색인합니다. 별도 복사본을 만들면 중복 ID 충돌이 날 수 있습니다.
- **철회:** `review_status: proposed` 또는 `rejected`로 바꿉니다. 기존 검색은 원본 변경/철회를 재검사해 옛 발췌를 숨깁니다. 재색인으로 검색 사본을 갱신합니다. 디스크/백업의 영구 삭제 보장은 별개입니다.
- **완료 확인:** 승인한 노트 한 건이 새 세션에서 출처와 함께 검색되고, 수정 후 새 내용이 보이며, 철회 후 발췌가 나오지 않는지 확인합니다. 이것이 첫 제2의 두뇌 사용 경로입니다. 현재 자동 저장/관계 조회/직원별 권한까지 완성됐다는 뜻은 아닙니다.

## 6. 검색이 안 될 때

- 파일/검색 범위가 같은 실제 작업공간인지, UTF-8 `.md`인지 확인합니다.
- approved인지, secret이 아닌지, 필수 필드·고유 ID·JSON 배열 tags·시간대가 있는 날짜인지 확인합니다.
- Obsidian 속성 편집 후 tags가 여러 줄 YAML 목록으로 바뀌면 소스 모드에서 `tags: ["jarvis"]` 형태로 되돌립니다. 날짜도 지원 예시처럼 명시합니다.
- `skipped`·`stale_documents`를 확인하고 수정 후 재색인합니다. 새 파일도 재색인 전에는 검색되지 않습니다.
- 색인 전체가 한 스냅샷이므로 하위 폴더별로 번갈아 색인하면 다른 폴더 결과가 빠집니다. 기본 `JARVIS-Vault` 전체를 기준으로 합니다.
- 해시 기반 어휘 검색이므로 동의어·말바꿈에 한계가 있습니다. 관련 결과 없음이 기억 자체의 부재를 증명하지 않습니다.

## 도구 계약과 운영 제한

아래는 구현의 기존 계약입니다. 위 사용 흐름이 이 범위를 넓히지는 않습니다.

## 호출

- `index_obsidian_vault(directory="JARVIS-Vault")`: 검토 승인된 `.md`만 스캔해 별도 `.jarvis-obsidian/knowledge.sqlite3` 인덱스를 만든다. 소스 노트는 수정하지 않는다.
- `search_obsidian_vault(query="검색어", limit=5)`: 경로·줄번호·발췌·메타데이터·유사도 반환. 기존 로컬 lexical hashing 검색을 재사용하며 의미 임베딩 검색은 아니다.
- `prepare_obsidian_context(query="검색어", max_chars=6000)`: 같은 검색(`limit=10`) 결과를 출처가 붙은 하나의 `context` 문자열로 묶는다. 아래 "문맥 준비" 참고.
- 일반 문서의 `.jarvis-index`는 유지한다. Vault 재인덱싱은 이전 Vault 인덱스 전체를 대체한다. 빌드 상한 초과 시 기존 인덱스를 유지한다.
- 같은 ID를 가진 승인 노트가 둘 이상이거나 인덱싱 중 노트가 바뀌면 빌드를 중단하고 이전 인덱스를 유지한다. ID는 대소문자를 구분한다. 검색은 발췌와 메타데이터가 같은 원본 버전인지 다시 확인하고 `source_sha256`을 함께 반환한다.

## 문맥 준비

`prepare_obsidian_context`는 읽기 전용이다. 새 DB·그래프·훅·자동 모델 프롬프트 삽입은 없고 모델도 호출하지 않는다.

- `query`는 1~500자, `max_chars`는 1000~12000 정수다. bool·실수·문자열 숫자는 거부한다.
- `max_chars`는 **`context` 문자열의 Unicode 코드 포인트 수** 상한이다(`used_chars == len(context)`). 토큰 수나 모델 전체 창 크기를 보장하지 않는다. 한글·이모지도 코드 포인트 단위로 센다.
- 후보는 기존 검색이 통과시킨 인덱싱된 승인·비secret 노트뿐이다. 인덱스가 없으면 빈 성공이 아니라 오류다. 결과가 없으면 `context`에 "NO SOURCES" 고정 문구만 넣고 답을 지어내지 않는다.
- 포함 직전에 원본을 다시 읽어 SHA-256·메타데이터·발췌를 검색 결과와 대조한다. 그 사이 수정·승인 철회된 노트는 발췌 없이 `stale_documents`에 경로만 남는다. 이는 스냅샷 검사이며 트랜잭션이 아니다. 마지막 검사 이후의 수정은 반영되지 않는다.
- `context`는 고정 머리말 + `SOURCE {JSON}` 한 줄씩 + 고정 꼬리말이다. 각 줄에 id·note_id·제목·경로·`source_sha256`·줄 범위·발췌가 JSON으로 들어 있어 노트 본문이나 여러 줄 제목이 머리말·출처 줄을 위조할 수 없다. 머리말은 질의와 노트 내용이 지시가 아닌 신뢰하지 않는 데이터임을 밝힌다.
- 출처 블록은 통째로 넣거나 통째로 뺀다. 예산 초과로 뺀 블록은 `omitted`에 `{id, reason:"budget"}`로만 남는다. `sources`에는 발췌 없이 인용 정보만 있다. id는 노트 ID·경로·해시·줄·발췌 해시로 정해지므로 다른 블록이 빠져도 바뀌지 않는다.
- 중지 표식은 오래된 노트로 처리하지 않고 오류로 끝난다. 호출 예산·중지 정책은 다른 도구와 같다.
- `external_transmission: false`는 이 함수가 노트를 외부로 보내지 않는다는 뜻일 뿐이다. 결과를 받은 MCP 클라이언트가 이를 외부 모델로 보낼 수 있으며 이 기능은 그것을 막지 못한다.

## 지원하는 frontmatter

전체 YAML이 아닌 **평면 필드만** 지원한다. 문자열은 JSON 쌍따옴표 또는 단순 한 줄 값/작은따옴표, tags는 JSON 문자열 배열이다. 중첩 맵·블록 문자열·별칭·객체 태그·중복/미등록 필드는 거부한다. created/updated는 시간대가 있는 ISO 시각이며 updated가 created보다 빠르면 거부한다.

```markdown
---
id: "jarvis-note-001"
title: "GitHub 우편함 설계"
created: "2026-10-22T21:00:00+09:00"
updated: "2026-10-22T21:00:00+09:00"
source: "manual"
tags: ["jarvis", "개발"]
sensitivity: "private"
review_status: "approved"
---
검토가 끝난 지식을 이곳에 기록한다.
```

`review_status`는 proposed/approved/rejected, `sensitivity`는 private/public/secret이다. approved이면서 secret이 아닌 노트만 검색한다. 자동 승인은 하지 않는다. Issue #7의 `00-Inbox`, `10-Knowledge`, `20-Projects`, `30-Decisions`, `40-Memory`, `50-Reviews`, `90-Archive` 구조는 선택적으로 직접 만든다. 디렉터리 이름보다 각 노트의 명시적 승인 상태를 기준으로 한다.

## 보안·제한

- 각 파일 최대 512,000 bytes, 전체 5,000,000 bytes, 200개 파일·2,000개 청크·2,000개 디렉터리 항목 상한은 기존 검색과 같다. 숨김 폴더·비 Markdown·링크·하드링크·잘못된 UTF-8·인식된 자격증명은 제외한다. redaction은 알려진 패턴 검출이며 비밀 탐지의 완전한 보장이 아니다.
- 검색 시 파일 해시와 승인 상태를 재검증한다. 변경·승인 철회된 파일의 캐시 발췌는 반환하지 않으며 재인덱싱 전 새 내용은 검색하지 않는다. 인덱스에는 이전 내용이 남을 수 있으므로 승인 철회 후 재인덱싱한다. 디스크·백업의 영구 삭제는 보장하지 않는다.
- `[[링크]]`, 첨부·임베드·source URL은 텍스트 데이터다. 따라가거나 다운로드·실행하지 않는다. 반환 발췌는 명령/승인으로 취급하지 않는다.
- 네트워크·클라우드 AI·유료 서비스·Obsidian Sync·Git push·새 백업 등록을 호출하지 않는다. Vault 내용이 저장소로 자동 업로드되는 기능도 없다.
- MCP 도구 결과는 호출한 클라이언트에 반환된다. 이 기능은 클라이언트가 이후 내용을 외부 모델로 보내는 것까지 통제하지 않는다. 개인 노트는 승인한 로컬 클라이언트에서만 조회한다.
- JARVIS 채팅의 모델 도구 선택 목록에는 Vault 도구를 넣지 않았다. 대신 노트를 언급한 질문만 서버가 직접 검색해 로컬 모델에 발췌를 주고 출처(제목·줄·`source_sha256`)를 답변에 붙인다(PA1-KNOWLEDGE, [채팅 안내](chat.md)). 협업·무료 배정 경로에는 노트를 넘기지 않는다. 채팅은 인덱싱하지 않는다.
- 기존 범용 문서 검색 도구의 작업공간 읽기 권한은 그대로다. Vault 승인 필터는 이 어댑터의 검색 정책이며 서버 전체의 파일 접근 ACL은 아니다. 직원별 신원·권한(W4-2)은 별도 미완료 과제다.
- 기존 백업 범위·설정은 바꾸지 않았다. 작업공간 내부 Vault는 기존 작업공간 백업에 포함될 가능성이 있으므로 실제 사용 전에 포함/제외 범위와 복원 정책을 확인한다. 자동으로 검증되거나 별도 백업이 보장된 것으로 간주하지 않는다.
- 합성 Vault·실행 중 WAL SQLite를 기존 `stage_data.stage`로 staging하고 별도 임시 경로에 복원한 검사에서 Markdown 해시·SQLite 무결성·복원 후 검색을 확인했다. 기본 작업공간 내부 Vault와 인덱스가 staging에 포함됐다. 실제 restic/R2 업로드·암호화·자격증명·일정·기존 백업 복구 검증은 수행하지 않았다. 사용자 데이터로 적용 전에 포함 범위를 확인한다.
