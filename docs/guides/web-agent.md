# 웹 작업 에이전트 (M2, 채팅 연결 M4a)

어떤 두뇌(기본 로컬 qwen 포함)든 공개 웹 작업 하나를 끝까지 하도록 자비스가 도구를 쥐고 실행하는 고리입니다. 코드는 `jarvis/features/web_agent/service.py`입니다.

## 처음 한 번: 설정

Node.js LTS가 설치되어 있어야 합니다. 프로젝트 폴더에서:

```
.\.venv\Scripts\python.exe scripts\setup_web_agent.py
```

`@playwright/mcp@0.0.83`을 `JarvisWorkspace/.jarvis-mcp/runtime`에 설치하고(실행 때 npx로 내려받지 않음), 권장 실행 옵션으로 서버 `pw`를 MCP 설정에 넣은 뒤, 서버가 알려 준 도구 중 `browser_navigate`·`browser_snapshot`·`browser_click`만 승인할지 묻습니다(나머지는 모델에게 보이지 않음). 이미 같은 버전이 설치된 폴더가 있으면 `--installed <...\@playwright\mcp\cli.js>`로 내려받기 없이 씁니다(버전을 확인함). 끝나면 HUD를 다시 시작합니다. 페이지 읽기는 자비스 자체 HTTPS 일꾼을 쓰므로 `mcp-server-fetch`는 필요 없습니다.

## 채팅에서 쓰기

- "찾아줘", "찾고", "검색해서", "알아봐줘", "조사해", "다운받아줘", "내려받아줘" 같은 요청이나 요청 분류가 웹 검색·페이지 읽기라고 판단한 요청은 이 에이전트가 답합니다. 메일·일정·로컬 문서·노트·PC 상태 요청은 들어오지 않습니다. 다운로드 폴더·바탕화면·폴더·내 PC·드라이브·로컬·`projects/`·Windows 경로처럼 이 PC의 장소를 말하는 요청도 웹·인터넷·사이트·온라인이나 http(s) 주소를 함께 말하지 않으면 기존 로컬 도구로 갑니다("다운로드 폴더 정리해줘"는 내려받기 요청이 아님).
- 답하는 모델은 모델 이름 버튼으로 고른 두뇌입니다. 대화 기록·노트·로컬 도구는 에이전트에 들어가지 않고, 요청 문장과 공개 페이지만 들어갑니다.
- 진행 중에는 지금 하는 일이 상태 한 줄로 보입니다: "검색 중: …", "페이지 여는 중: 주소", "버튼 누르는 중: …", "받는 중: …", "실패: …". 답변이나 초안이 아니라서 소리 내어 읽지 않고, 비서 화면의 고리는 "생각 중" 모양을 유지합니다. 최종 답이 오면 사라집니다.
- 화면용 데이터: 대화 조회의 각 요청(turn)에 `progress`가 붙습니다(진행 중일 때만, 끝나면 `{}`). 필드는 `kind`(`web`), `phase`(`search`/`page`/`download`/`failed`), `line`(지금 하는 일 한 줄), `step`/`step_limit`(행동 수/상한 30), `pages_read`/`page_limit`(읽은 페이지/상한 10), `host`(지금 여는 사이트), `hosts`(읽은 사이트, 최대 10), `recent`(최근 줄 최대 6)입니다. 최대 4 KiB이며 비밀값 가림을 거칩니다. `draft`는 답변 글에만 씁니다.
- 멈추기: `POST /api/chat/stop`(본문 `{}`, 채팅과 같은 토큰·Origin 검사). 다음 단계 전에 끝나고 지금까지 읽은 출처와 함께 "사용자가 작업을 멈췄습니다."로 남습니다. 이미 시작한 모델 호출 하나는 끝까지 기다립니다. 화면의 멈춤 버튼은 다음 단계입니다.
- 최종 답 아래에 자비스가 실제로 읽은 페이지 주소("출처:")와 받은 파일·상태·저장 폴더가 붙습니다.
- 작업 하나는 10분까지라 그 턴의 저장 기한은 660초입니다. 웹 작업 하나는 대화의 모델 예산을 1회분만 쓰고, 그 안의 모델 호출은 작업 자체 한도(30회)로 셉니다. 웹 작업은 하루(이 PC 날짜) 100회까지입니다(`JarvisWorkspace/.jarvis-chat/web_tasks.json`).
- 외부 모델: 검색·페이지 결과는 공개 웹(public_web)이라 외부 모델에 갈 수 있습니다. 내려받기가 있었던 턴(`web_download`)은 로컬 전용이라 이후 외부 모델 문맥에서 빠집니다.
- 설정이 없을 때: 내려받기 요청은 설정 안내로 답하고, 검색 요청은 기존 채팅 검색(발췌 3개)이 답합니다. Node.js가 없거나 도구가 바뀌었거나 서버가 시작되지 않으면 그 이유와 할 일을 답합니다.

## 모델이 고르는 것
매 단계 모델은 JSON 스키마의 선택지 하나만 고릅니다. 브라우저 도구를 직접 받지 않습니다.
- `search(query)`: 브라우저로 Bing 결과 페이지를 열고 자비스가 결과를 번호로 정리합니다(Bing 추적 링크는 원래 주소로 풉니다).
- `open(number)`: 번호 붙은 검색 결과·요청에 적힌 주소·페이지 링크를 엽니다. HTTPS 읽기 일꾼을 먼저 쓰고, 본문이 짧거나 실패하면 브라우저로 엽니다.
- `press(number)`: 지금 브라우저에 열린 페이지의 버튼을 누릅니다. 로그인·가입·결제·주문·글쓰기·전송·삭제 같은 버튼은 아예 보여주지 않고, 누를 때 한 번 더 막습니다.
- `download(number)`: 사용자 요청에 내려받기 말이 있을 때만 나옵니다.
- `answer(answer, sources)`: 최종 답과 근거 페이지 번호. 자비스가 실제로 읽은 페이지 주소로 "출처:" 목록을 붙입니다.

모델이 같은 검색을 되풀이하면 자비스가 결과 중 하나를 대신 엽니다(요청에 적힌 주소, 공공기관 주소 순, 블로그·질문 사이트는 뒤로). 읽은 페이지에 공식 출처(공공기관 주소나 요청에 적힌 주소)가 없는데 답하려 하면, 한 번만 공식 사이트를 찾아 확인하라고 되돌려 보냅니다.

번호는 이 작업에서 자비스가 건넨 것만 고를 수 있어서, 모델이 주소를 만들거나 바꿀 수 없습니다. 이미 한 행동은 다시 나오지 않습니다(같은 검색어도). 스키마에 없는 선택은 거부하고, 3번 틀리면 답만 고르게 합니다.

## 주소 관문
- 브라우저가 가기 전에: https, 443 포트, 계정·토큰 같은 매개변수 없음, DNS 주소가 모두 공인 주소(`validate_url`, `public_addresses`).
- 페이지가 열린 뒤: 최종 "Page URL"을 다시 검사하고, 공인이 아니면 `about:blank`로 떠나며 내용을 읽지 않습니다.
- 첫 겹으로 Playwright에 `--blocked-origins`(localhost, 127.0.0.1, ::1)를 줍니다. 공식 문서상 보안 경계가 아니라서 자비스 검사가 본 관문입니다.
- 알려진 한계: 버튼(`press`)은 눌렀을 때 어디로 갈지 스냅숏에 주소가 없어서, 누르기 전 주소 검사를 못 합니다. 버튼이 사설 주소로 GET 요청을 보내면 막는 것은 `--blocked-origins`(localhost)와 도착 후 최종 주소 검사뿐이고, 그 페이지 내용은 읽지 않습니다. 링크(`open`)는 언제나 가기 전에 검사합니다.

## 한도 (기본값)
- 작업당 도구 30회, 10분, 검색 4번. 마지막 45초는 답 고르기에 남깁니다. 시간이 다 되면 실패로 끝냅니다.
- 페이지는 작업당 10개까지(사용자 결정 2026-10-29), 검색 결과·요청 주소에서 링크를 2번까지 따라갑니다.
- 결과 8개, 새 페이지 본문 3000자, 링크 20개, 버튼 8개.
- 페이지 메모: 모델은 페이지를 받은 다음 단계에서 그 페이지의 요청 관련 사실을 `notes`(400자 이내)에 적습니다. 그 뒤로 그 페이지는 본문 대신 이 메모(메모가 없으면 본문 앞 300자)로만 남고, 최근 2개 페이지만 번호 붙은 링크를 프롬프트에 남깁니다(더 오래된 링크도 번호로는 열 수 있음). 최종 답은 이 메모들로 씁니다.
- 프롬프트는 약 12000자 안으로 유지합니다(로컬 채팅 일꾼이 8192토큰 문맥).
- 빈 답은 한 번 다시 묻고, 또 비면 실패로 끝냅니다. 중지 표시(`.jarvis-stop`)는 매 단계 확인합니다.

## 내려받기
- 파일은 Playwright 출력 폴더(격리 폴더)에만 떨어집니다. 열거나 실행하지 않습니다.
- 허용 확장자: pdf, csv, txt, json, png, jpg, gif, xlsx, docx, pptx, hwp, hwpx, xls. 확장자와 첫 바이트가 맞아야 하고 20MB 이하여야 합니다.
- Microsoft Defender로 검사합니다. 깨끗하면 `downloads` 폴더로 옮기고, 위협이면 지우고, 검사를 못 하면 격리 폴더에 둔 채 저장 완료로 알리지 않습니다.
- 옮긴 파일에는 인터넷에서 받은 파일 표시(Mark of the Web, `Zone.Identifier` ZoneId=3과 받은 주소)를 붙여 Windows가 열기 전에 경고하게 합니다.
- 한 번에 받은 새 파일은 3개까지만 검사·보관하고, 나머지는 지우고 거부로 보고합니다. 검사 안 된 파일이 남지 않습니다.
