# 자비스 데스크톱 앱 (Windows)

브라우저 대신 쓰는 창입니다. 앱이 [로컬 작업 화면](local-hud.md) 서버를 직접 켜고 비서 화면(`/assistant`)에 자동으로 연결합니다. 트레이, 단축키, 미니 고리 창을 더했습니다. Tauri v2로 만들었고 코드는 `desktop/`에 있습니다. v1은 이 PC 전용입니다. 저장소의 `.venv` Python을 쓰고, 설치 파일과 코드 서명은 없습니다.

## 빌드와 실행

Rust(stable-msvc)와 Visual Studio C++ 빌드 도구가 필요합니다. 프로젝트 루트에서 실행합니다.

```powershell
cd desktop
cargo build --release
.\target\release\jarvis-desktop.exe
```

- 앱은 실행 파일 위치에서 위로 올라가며 저장소(`server.py`와 `jarvis/cli/hud.py`가 있는 폴더)를 찾습니다. `JARVIS_ROOT`로 직접 지정할 수 있습니다.
- Python은 저장소의 `.venv\Scripts\python.exe`를 씁니다. 다른 경로는 `JARVIS_PYTHON`으로 지정합니다.
- 포트는 기본 8787입니다. 이미 쓰는 중이면(예: 브라우저용 화면 서버를 따로 켜 둔 경우) 알림 창을 띄우고 종료합니다. 같은 데이터에 서버 두 개가 붙지 않게 하려는 것입니다. 시험용으로만 `JARVIS_DESKTOP_PORT`로 바꿉니다.
- 빌드 산출물(`desktop/target/`), 자동 생성 파일(`gen/`, `permissions/autogenerated/`), 빌드 때 복사하는 `dist/orb.js`는 Git에서 제외합니다.

## 동작

- **서버**: 앱이 `python -X utf8 -m jarvis.cli.hud --shell`을 자식 프로세스로 실행합니다. 이 프로세스는 Windows 작업 개체(job object, KILL_ON_JOB_CLOSE) 안에 있어서, 앱이 강제 종료되거나 멈춰도 서버와 서버가 띄운 프로세스가 함께 끝납니다.
  - 자식은 만들어지는 순간부터 작업 개체 안에 있습니다. CreateProcessW에 `PROC_THREAD_ATTRIBUTE_JOB_LIST`(Windows 10 이상)를 넘기기 때문에, 만든 뒤 넣는 방식과 달리 작업 개체 밖에서 실행되는 틈이 없습니다.
  - 자식에게 넘어가는 핸들도 `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`로 파이프 세 개로만 제한합니다.
  - 표준 Rust의 프로세스 생성 기능(`std::process::Command`)은 stable에서 이 속성들을 지정할 수 없어서 직접 호출합니다(`desktop/src/server.rs`).
- **서버 감시**: 서버가 스스로 멈추면 앱이 0.5초 안에 알아채고 다시 시작합니다.
  - 기다리는 시간은 1, 2, 4, 8, 16초로 늘어납니다. 연속 5번 실패하면 더 시도하지 않습니다(`desktop/src/watch.rs`).
  - 60초 이상 정상으로 돌던 서버가 멈춘 것은 새로 센 첫 번째 실패로 봅니다.
  - 다시 시작하는 동안 큰 창은 "다시 시작하는 중 (n/5)"를, 포기한 뒤에는 멈춤 안내를 보여 줍니다. 트레이 아이콘 설명도 같은 상태를 보여 줍니다.
  - 포기한 뒤에는 트레이 메뉴의 **서버 다시 시작**이 켜지고, 누르면 처음부터 다시 셉니다.
  - 다시 시작하면 새 일회용 연결 코드로 자동으로 다시 연결합니다.
  - 앱을 종료(트레이 메뉴의 종료, 앱 종료)할 때는 서버를 멈추고 다시 시작하지 않습니다.
  - 처음 시작에 실패하면(예: 포트 사용 중) 지금처럼 알림 후 종료합니다.
- **자동 연결**: `--shell` 서버는 브라우저를 열지 않습니다. 준비되면 일회용 연결 주소 한 줄을 앱과 연결된 stdout 파이프로만 넘깁니다. 이 코드는 브라우저 자동 연결과 같은 5분짜리 일회용 코드이고, 페이지가 읽자마자 주소에서 지웁니다. 연결 파일 값은 주소나 로그에 들어가지 않습니다. 기존 인증과 CSP는 그대로입니다.
- **창**: 큰 창을 닫으면 종료되지 않고 트레이로 숨습니다. 앱은 한 번만 실행되며, 두 번째로 실행하면 기존 창을 보여 주고 끝납니다. 큰 창은 로컬 서버 주소만 엽니다. 채팅의 외부 링크(http/https)는 기본 브라우저로 열고, 그 밖의 주소는 열지 않습니다.
- **단축키**: Ctrl+Alt+J로 큰 창을 보이거나 숨깁니다.
  - Win 키 조합은 Windows가 예약한 것이 많아서 피했습니다. Ctrl+Alt+J는 흔한 앱 단축키와도 잘 겹치지 않습니다.
  - 다른 프로그램이 이미 쓰고 있으면 트레이 아이콘의 설명에 등록 실패를 표시합니다.
- **트레이 메뉴**: 열기, 숨기기, 미니 고리, 로그인 시 자동 실행, 서버 다시 시작(멈춘 뒤에만 켜짐), 종료. 아이콘을 왼쪽 클릭하면 큰 창을 보이거나 숨깁니다.
- **로그인 시 자동 실행**: 기본은 꺼짐입니다. 트레이 메뉴에서 켜면 현재 사용자의 시작 프로그램(HKCU Run)에 `--hidden`으로 등록됩니다. 로그인할 때 창 없이 트레이로만 시작합니다.
- **미니 고리**: 트레이 메뉴로 켭니다. 배경이 투명하고 항상 위에 뜨는 작은 창이며, 작업 영역 오른쪽 아래에 나타납니다.
  - 비서 화면과 같은 원형 표시(`frontend/assistant/orb.js`를 빌드할 때 복사)로 큰 창의 상태(대기, 듣는 중, 생각 중, 답하는 중, 오류)를 따라갑니다.
  - 클릭하면 큰 창이 열리고, 끌면 위치가 바뀝니다.
  - 서버에 따로 연결하지 않습니다.

## IPC 경계

앱과 페이지 사이의 호출은 앱 명령 세 개로만 열어 두었습니다. 다른 Tauri 기능 권한은 주지 않았습니다.

| 창 | 허용 명령 | 내용 |
|---|---|---|
| 큰 창의 서버 페이지(`http://127.0.0.1:<실제 포트>/*`) | `presence` | 상태 이름 7개 중 하나만 받아 미니 고리에 전달 |
| 미니 고리(앱 내장 페이지) | `expand`, `drag` | 큰 창 열기, 미니 창 끌기 |

서버 페이지 권한은 파일로 두지 않습니다. 앱이 시작할 때 실제 포트로 추가합니다(`main.rs`의 `server_page_url`). 포트를 `JARVIS_DESKTOP_PORT`로 바꿀 수 있어서 정적 파일에서는 포트 와일드카드(`127.0.0.1:*`)가 필요했기 때문입니다. 이 권한은 앱 내장 페이지에는 적용하지 않습니다(`local(false)`). 미니 고리 권한은 `desktop/capabilities/mini.json`에 있습니다.

명령은 호출한 창의 이름도 다시 확인합니다. 비서 화면은 앱 안에서 열렸을 때만 `presence`를 부르고, 일반 브라우저에서는 아무것도 보내지 않습니다.

## 검증과 측정 (2026-10-28, 이 PC)

- 테스트:
  - `cargo test`(desktop/에서 실행): 15개입니다. 확인하는 것은 다음과 같습니다.
    - READY 줄 검증, 저장소 찾기
    - 자식이 생성 순간부터 작업 개체 안에 있는지, 출력이 파이프로 오는지, 작업 개체를 닫으면 손자 프로세스까지 끝나는지
    - 명령줄 인용
    - 재시작 대기·상한·초기화
    - 상태 화면 주소, 트레이 문구, 정확한 포트의 권한 주소
    - 이동 허용 범위, 외부 링크, 상태 이름 일치
  - 비서 화면의 앱 연동은 `tests/frontend/assistant.test.cjs`, `--shell`은 `tests/test_hud_connect.py`에서 확인합니다.
- 실제 앱 점검은 `.\.venv\Scripts\python.exe scripts\desktop_smoke.py <exe> <출력폴더>`로 합니다. 릴리스 빌드로 3번 실행한 결과는 다음과 같습니다.
  - 창이 뜨기까지 0.11~0.23초, 서버 준비까지 1.2~1.6초 걸렸습니다.
  - 자동 연결, 단축키, 닫으면 트레이로, 단일 실행을 확인했습니다.
  - 앱을 강제 종료하면 서버도 종료되는 것을 확인했습니다.
  - 디버그 빌드에서는 미니 고리도 확인했습니다. 투명 배경, 생각 중일 때 주황색, 클릭하면 큰 창이 열립니다.
  - 서버 감시(2026-10-28, 디버그 빌드 3번):
    - 서버를 강제로 끝내면 2.2~2.4초 안에 새 서버가 뜨고, 페이지가 다시 `idle`까지 연결됩니다. 디버그 빌드는 `presence` 호출을 출력하고 smoke가 읽습니다.
    - 새 서버를 계속 끝내면 5번 다시 시작한 뒤 멈추고, 남은 서버가 없으며, 큰 창에 멈춤 안내가 보입니다.
    - 미니 고리 클릭은 3번 중 2번 통과했습니다. 실패한 1번은 마우스 자동 조작 시점 문제로 보입니다.
- 메모리(대기 중, 앱·WebView2·Python 서버 전용 메모리 합): 277~354MB입니다.
- 실행 파일: 릴리스 7.6MB, 서명 없음.
- SmartScreen: 인터넷에서 받은 것처럼 표시(Zone.Identifier, ZoneId=3)한 사본을 `Start-Process`로 실행했을 때 경고 없이 실행됐습니다. 이 PC의 스마트 앱 컨트롤은 꺼져 있습니다(상태 0). 탐색기에서 더블클릭하는 경우와 다른 PC는 확인하지 않았습니다. 직접 빌드한 파일에는 이 표시가 없으므로 보통은 해당하지 않습니다.
- 시작 시간 기록: 앱은 시작할 때마다 `%LOCALAPPDATA%\dev.jarvis.desktop\startup.log`에 한 줄을 남깁니다(`uptime_s`, `ready_ms`). 연결 주소와 코드는 기록하지 않습니다.
  - 측정한 3번은 부팅 후 약 49분이 지난 뒤였고 `ready_ms`는 1195~1396이었습니다.
  - 콜드 부팅 직후의 값은 자동 실행을 켜고 재부팅한 뒤 이 파일에서 확인합니다. `uptime_s`가 작은 줄이 부팅 직후입니다. 아직 측정하지 않았습니다.

## 한계

- 설치 파일, 자동 업데이트, 코드 서명이 없습니다. Python을 함께 넣지 않으므로 저장소와 `.venv`가 있는 이 PC에서만 실행합니다.
- 서버는 시작할 때 일회용 코드로 한 번 연결합니다. 5분이 지난 뒤 큰 창을 새로고침하면 그 탭에 저장된 연결값으로 다시 연결합니다. 저장된 값이 없으면 앱을 다시 시작합니다.
- 미니 고리는 상태만 따라가고 음성 크기나 파형은 받지 않습니다. 누르고 말하기 같은 음성 단축키는 음성 서비스가 생긴 뒤에 붙일 예정입니다.
