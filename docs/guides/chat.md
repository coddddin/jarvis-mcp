## 실행과 연결

설치된 Ollama를 먼저 실행하고 프로젝트 루트에서 다음을 실행합니다. 기본 모델은 설치된 `qwen3.5:9b`이며 자동 다운로드하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m jarvis.cli.hud --port 8788 --open
```

`http://127.0.0.1:8788`에서 **연결 파일 선택**을 눌러 프로젝트의 `.jarvis-auth/agent-events-token.txt`를 선택합니다. 토큰 내용은 채팅·주소창·로그에 붙여넣지 않습니다. 현재 창의 메모리에서만 사용하며 새로고침하면 다시 선택해야 합니다. 저장된 에이전트 작업이 없어도 채팅을 시작할 수 있습니다. 기존 start-hud.cmd의 기본 8787 포트도 같은 기능을 제공합니다. 이전 버전 서버는 별도로 재시작해야 합니다.

HUD가 포트를 연 직후 채팅 모델을 백그라운드에서 한 번 미리 불러옵니다(빈 메시지로 불러오기만 하고 답변은 만들지 않으며, 실패해도 무시). 채팅 모델은 마지막 사용 후 5분 동안 GPU 메모리(이 모델은 약 5GB)에 남아 있어 그동안의 첫 글자가 빨리 나옵니다([ADR 0001](../adr/0001-hardware-resource-policy.md)). 5분 넘게 쉬면 Ollama가 모델을 내립니다. 다시 불러오는 데 약 4.5초가 걸리므로, 입력창에 쓰기 시작하거나 마이크가 열리는 순간(Space, 마이크 버튼) 미리 불러옵니다(`POST /api/chat/warm`, 페이지에서 1분에 한 번 이하, 서버에서 한 번에 하나). 미리 불러오기가 실패해도 무시하고, 첫 답변이 모델을 직접 불러옵니다. 로컬 협업 작업자는 별도로 2분 유지를 씁니다.

인증 후 **자비스와 대화 / 작업 현황** 탭으로 이동합니다. 새 대화와 이전 대화를 선택할 수 있고 Enter로 보내기, Shift+Enter로 줄바꿈합니다. 답변 준비 중 중복 전송을 막습니다. 로컬 모델이 최종 답변을 쓰는 동안에는 받은 만큼을 흐리게 **작성 중 · 확인 전**으로 보여 줍니다(약 0.4초 간격 조회). 이 초안은 근거 확인 전이라 최종 답변으로 바뀌거나 실패하면 사라질 수 있으니 그대로 따르지 마세요. 서식은 최종 답변에만 적용합니다. 중지 버튼은 아직 없고, 창을 닫아도 서버는 시간 제한까지 답변을 마쳐 저장합니다. 자비스 답변은 코드 블록, 인라인 코드, 굵게, 제목(#~###), 목록, http(s) 링크만 서식으로 표시하고 나머지는 글자 그대로 둡니다. 서식은 HTML 문자열 없이 화면 요소로만 만들며, 다른 주소 형식의 링크는 글자로 남습니다. 내가 보낸 메시지는 서식 없이 그대로 표시합니다.

**오늘 브리핑** 카드는 탭 바로 아래 공통 영역에 하나만 있어 **자비스와 대화**와 **작업 현황** 어느 탭에서도 보입니다. 처음에는 대화창을 가리지 않도록 "오늘 브리핑 · 일정 2개 · 첫 일정 10:00 회의 · 안 읽은 메일 약 5통" 같은 한 줄 요약으로 접혀 있고, 누르면 일정과 메일 목록이 펼쳐집니다. 연결마다 한 번(그리고 새로고침 버튼) 불러오며, 탭을 바꾸는 것만으로는 다시 요청하지 않고, 연결 해제 시 내용을 지웁니다.

별도의 진행 방식 선택 없이 요청을 보내면 화면은 `mode=auto`를 전달합니다. 요청을 저장한 뒤 로컬 모델이 먼저 대화/로컬 협업, 일반/외부/로컬 근거 필요, 검색/원문 조회, 실행 미지원 여부를 분류합니다. 최근2개 대화의 각 사용자/답변500자 이내를 참고합니다. 분류는25초 내1회이며 실패하면 요청을 실패로 남기고 자동 재시도하지 않습니다. 결과는 request_plan, 원래 요청 방식은 requested_mode로 저장합니다. 중복 요청은 분류나 작업을 다시 수행하지 않습니다. 기존 기록은 보존하며 이전 버전의 자동 요청은 원래 방식 식별 정보가 없으면 같은 ID의 재전송이 거부될 수 있습니다.

외부 정보가 필요하다는 사전 판정은 최종 답변의 general 자기분류로 해제되지 않습니다. 로컬 관찰에는 성공한 로컬 도구 근거를 요구합니다. 분류 자체도 모델의 판단이므로 오분류 가능성은 있으며 기존 문구 검사도 보조로 유지합니다. 외부 AI 협업은 자동 선택하지 않고 기존 명시적 혼합 API/CLI를 유지합니다. 웹 검색어는 Bing에 전달되며, 혼합 협업은 현재 요청·생성 결과의 외부 AI 전송과 계정 사용량이 발생할 수 있습니다.

협업 중 인증된 대화 조회로 역할별 진행을 갱신합니다. 응답 전달 완료와 협업 결과는 별도로 표시하며, `needs_user_input`은 사용자 확인 필요입니다. 모델 검토 통과는 코드 실행 검증이 아닙니다. 수정 횟수·상한 종료 사유와 도구 근거 ID·UTC 조회 시각을 표시합니다. 이전 서버/열린 화면은 재시작/새로고침이 필요합니다.

## 웹 작업 (M4a)

찾기·검색·내려받기 요청은 브라우저를 쓰는 웹 작업 에이전트가 답합니다. 처음 설정, 진행 줄, 멈추기(`POST /api/chat/stop`), 출처·파일 표시, 외부 모델 규칙은 [웹 작업 에이전트](web-agent.md)에 있습니다. 설정 전에는 검색 요청을 아래 기존 검색이 답합니다.

## 답하는 모델 고르기

채팅 머리말(대화 화면)과 자비스 화면 위쪽 상태 줄 옆에 **지금 답하는 모델 이름 버튼**이 있습니다. 누르면 연결된 모델 목록이 나오고, 고르면 **다음 질문부터** 그 모델이 답합니다. 이미 답을 만들고 있는 질문은 시작할 때의 모델로 끝까지 답합니다. 바꾸기에 실패하면(설치 안 됨, Ollama 응답 없음, 로그인 안 됨 등) 지금 모델을 그대로 쓰고 이유를 보여 줍니다. 각 답변 아래에는 실제로 답한 모델(`답한 모델: …`)이 표시됩니다.

- 범위: 고른 모델은 **채팅과 음성 답변에만** 쓰입니다. 요청 분류, 웹 검색어 준비, 로컬 협업, 리드·작업 판정, Wiki 검토는 항상 로컬 기본 모델(`hud --model`, 기본 `qwen3.5:9b`)이 합니다.
- 로컬 모델: 이 PC의 Ollama에 설치된 모델 중 대화용(`completion`)이고 이 PC에서 도는(gguf, 원격 아님) 모델만 고를 수 있습니다. 자동으로 내려받지 않습니다.
- 저장: 선택은 `JarvisWorkspace/.jarvis-settings/brain.json`에 남습니다. 제공자·모델 이름과 외부 사용 확인 여부만 들어 있고 비밀값은 없습니다. 파일이 없거나 깨졌으면 로컬 기본 모델을 씁니다.
- API: `GET /api/brain`(목록·현재 선택), `POST /api/brain/selection`(`provider_id`, `model_id`, 선택 `confirm_external`). 채팅 API와 같은 토큰·Host·Origin 검사를 거칩니다.

### 외부 모델에 보내는 것 (사용자 결정 2026-10-28)

이 PC 밖에서 답을 만드는 모델(외부 모델)을 처음 고를 때는 아래 목록을 보여 주고 **확인하고 사용**을 눌러야 바뀝니다. 목록은 화면·서버·이 문서가 같은 코드 상수(`jarvis/agents/brain.py`의 `EXTERNAL_SENDS`, `NEVER_SENT`)를 씁니다.

- 보내는 것: 지금 대화(질문과 앞선 답변), 공개 웹 검색 발췌·공개 페이지·등록된 공개 피드, PC 상태(CPU·메모리·디스크), 승인된 Vault 노트 발췌(출처 포함).
- 보내지 않는 것: 메일, 일정(캘린더), 오늘의 브리핑, 로컬 문서, 프로그램 정적 분석(REA) 결과, 승인되지 않은 노트, 비밀번호·키 같은 비밀값.
- 허용 목록 방식입니다. 위 "보내는 것"에 없는 도구·출처는 새로 추가되더라도 기본으로 로컬 전용입니다.
- 메일·일정·브리핑·로컬 문서·REA·미승인 노트를 가리키는 질문은 외부 모델을 골라 두었어도 **로컬 기본 모델이 답하고**, 답변 아래에 "… 내용은 외부 모델에 보내지 않아서 로컬 모델이 답했습니다."라고 이유를 보여 줍니다.
- 외부 모델에는 허용 목록 안의 도구만 줍니다. 앞선 대화 중 로컬 전용 자료로 답한 턴(로컬 문서·REA 결과를 쓴 턴, 로컬 모델이 대신 답한 턴, 협업 턴)은 질문과 답 모두 `[로컬 전용 … 생략]`으로 바꿔 보냅니다.
- 외부 모델이 실패하면(한도, 로그인, 시간 초과 등) 그 질문은 실패로 남고 이유를 보여 줍니다. 다른 모델(로컬 포함)로 자동 전환하지 않습니다.
- 질문 문구 판별은 표현 목록 기반이라 빠지는 말이 있을 수 있습니다. 그래도 외부 모델은 허용 도구와 걸러진 문맥만 받으므로 로컬 전용 자료가 전달되지는 않습니다.

고를 수 있는 외부 모델은 [Claude 구독 두뇌](#claude-구독-두뇌)와 [API 키 두뇌](#api-키-두뇌)(Claude·GPT·Gemini·Grok·DeepSeek)입니다.

## 가능한 기능

- 한국어 일반 대화와 같은 대화의 최근 문맥 유지.
- PC CPU·메모리·디스크 조회.
- 기존 로컬 문서 인덱스 검색. 인덱스가 없으면 기존 인덱싱 절차가 먼저 필요합니다.
- 등록된 공개 웹 출처 목록 조회와 Agent Reach RSS 읽기.
- 공개 웹 검색: Bing 검색 발췌 최대3개와 출처·UTC 조회 시각. 원문 확인이나 실시간 순위 검증이 아닙니다. 공개 검색어만 전송하며 비밀정보를 넣지 않습니다.
- 검색한 페이지 원문 일부 읽기: 현재 요청의 성공 검색 URL만 열고 최대3000자 정적 텍스트와 출처·조회 시각을 표시합니다. 전체 문서·JS 렌더링·사실 검증과 구분합니다.
- 현재 메시지에 정확한 `projects/...` 경로를 명시한 JS/PE 파일의 REA 정적 분석. 입력 프로그램을 실행하지 않습니다.
- 승인된 Vault 노트 검색(PA1-KNOWLEDGE v1): "내 노트에서", "그 메모에"처럼 노트 안을 찾거나 "정리해 둔/적어 둔/기록해 둔"이 들어간 질문, 또는 "내/제 노트·메모·옵시디언·자료"처럼 자기 노트를 가리키되 방법·앱·설정·동기화·백업·추천 같은 사용법 질문이 아닌 경우만 기존 `search_obsidian_vault` 색인을 검색합니다. 패치노트·갤럭시 노트·220볼트·제 볼트 규격·HashiCorp Vault·메모장·"내 노트 앱 추천" 같은 말은 일반 질문으로 처리합니다. 검색어에서는 "내 노트에서", "찾아줘" 같은 말을 빼고 점수를 매깁니다. 유사도 0.06 이상인 노트(최대 3개)가 있으면 답하는 모델(기본 로컬, 외부 모델을 골랐으면 그 모델)이 발췌만 보고 답하고, 답변 아래에 노트 제목과 줄 위치를 출처로 보여 줍니다. 모델이 인용하지 않은 노트는 "답변 인용 확인 안 됨"으로 따로 표시합니다. 이 턴에는 다른 도구를 쓰지 않습니다. 관련 노트가 없거나 색인이 없으면 모델 없이 그렇다고 안내합니다. 색인은 채팅이 만들지 않으므로 새로 승인한 노트는 `index_obsidian_vault`를 다시 실행해야 검색됩니다.
- 노트 내용과 외부 도구는 한 턴에서 만나지 않습니다. 노트로 답한 뒤의 턴들(요약 같은 후속 답변 포함)은 노트 내용을 담은 것으로 보고, 그 대화를 이어 갈 때는 웹 검색·페이지 읽기·등록 출처·피드 도구를 끕니다. 웹·검색·뉴스·날씨 같은 말이 들어간 질문은 반대로 그 턴들을 문맥에서 빼고 외부 도구를 씁니다. 원본이 바뀌거나 철회된 노트가 있으면 그 노트로 답한 턴부터 이후 턴까지 모두 모델 문맥에서 빠집니다(저장된 대화 기록 자체는 남습니다). 노트를 무료 API·외부 직원에게 넘겨 달라는 요청은 거절하고, 협업·무료 배정 경로는 노트를 검색하지 않습니다. 이 표현 목록에 없는 질문은 일반 대화로 처리됩니다.

예: “내 PC 상태를 확인해줘”, “등록된 웹 출처를 확인하고 BBC 뉴스를 읽어줘”, “projects/demo/input.js를 정적으로 분석해줘”. 예제 경로는 실제 존재하는 프로젝트 파일로 바꿉니다.

채팅은 기존 플러그인의 가드레일 래퍼를 호출합니다. 임의 셸·브라우저 로그인/쿠키·이메일 읽기·화면 캡처·파일 이동/삭제·코드 적용·프로그램 실행은 채팅 도구 목록에 포함하지 않았습니다. 기존 운영자 CLI와 MCP 기능은 유지합니다. 모델 출력은 작업 권한을 승인하지 않습니다.

## 말투

모든 답변 지시문은 `jarvis/app/chat.py`의 `PERSONA`로 시작합니다. 차분한 합니다체, 호칭 "주인님"(한 답변에 한 번 이하), 결론 먼저 1~3문장, 가벼운 상황에서만 가끔 건조한 위트(오류·보안·민감한 내용에는 쓰지 않음)입니다. 사실 확인·도구·안전 규칙은 그 뒤에 이어지며 말투 규칙보다 우선합니다. 고정 안내 문구도 같은 합니다체를 씁니다.

## 보관과 제한

무료 에이전트 연결부: “무료 API 에이전트로 함수 제안을 만들어줘” 같은 명시적 요청 또는 API의 `mode=free`는 기존 로컬 모델을 호출하지 않고 무료 배정기로 전달합니다. 현재 서버의 기본 후보/실행기 목록은 비어 있으므로 실행 가능한 무료 후보 없음으로 멈춥니다. OpenCode 앱에서 답한다는 사실만으로 자동 호출 준비를 완료 처리하지 않습니다. 구독·유료·비용 미확인 후보로 자동 전환하지 않습니다. 기존 명시적 로컬/혼합 협업 기능은 유지합니다.

연결부는 별도 검증된 adapter만 실행할 수 있고, 접근 확인 유효기간·비용·작업 종류·문맥·요청 예산을 적용합니다. 최대3회/기본12000 토큰 예약을 요청 전체에서 공유하고, 호출 전에 SQLite에 예약을 원자적으로 저장합니다. 확인된 rate/quota/context 한도 실패만 다른 무료 후보로 전환합니다. 시간 초과나 응답 여부가 불명확한 일반 예외는 unknown으로 남기고 재실행하지 않습니다. 재시작 후 자동 복구/재실행 기능은 없습니다. 실제 제공자 과금·전체 계정 한도를 계측하는 기능과 구분합니다.

응답 전달 완료와 `turn.dispatch.status`의 실행 판정은 별개입니다. 화면은 후보 제외 이유·예약된 호출·미확인 호출·보존 결과를 표시합니다. 제공자 결과는 제안이며 독립 검수·코드 실행·파일 적용은 아닙니다. 입력 추정은 UTF-8 바이트 수+512, 출력 예약1024이며 실제 토큰량과 다를 수 있습니다.

대화는 `JarvisWorkspace/.jarvis-chat/conversations.sqlite3`에 로컬 저장되며 기본 문서 검색 인덱스와 분리됩니다. 로컬 모델은 고정 loopback Ollama에만 요청합니다. 외부 모델을 고른 경우의 전송 범위는 위 "외부 모델에 보내는 것"을 따릅니다. 피드를 요청할 때는 기존 등록형 웹/Agent Reach 경로로 공개 출처에 접근합니다. 단일 로컬 사용자용이며 사용자별 로그인·원격 접속 서비스가 아닙니다.

- 최대 대화 100개, 대화당 요청 40개. 자동 삭제하지 않으며 보존/정리 정책은 후속 기능입니다.
- 메시지 2,000자, 답변 6,000자 이하. 최근 완료 대화 중 합계 6,000자까지 문맥으로 사용합니다. 전체 기록이 모두 모델에 전달되지는 않습니다.
- 일반 채팅의 의사결정 모델 호출 최대3회, 도구 최대2회. 비ASCII 검색어 준비가 최대2회 추가되어 명시적 chat은 최대5회, 자동 분류1회를 포함한 auto 일반 채팅은 최대6회입니다. 매 추론에 기존9216토큰 상한 예약을 차감합니다. 자동 분류25초와 후속 채팅 공유140초를 두며 자동 일반 요청의 저장 기한은 승인 후180초, 협업은 기존660초 이내입니다. 마지막 의사결정 호출은 답변만 허용합니다. 협업 내부 호출 예산은 별도 협업 안내를 따릅니다.
- 모델 호출당 입력/출력 예약 9,216토큰, 대화당 64회분 상한. 실제 토큰 계측이 아닌 상한 예약이며 실패해도 환불하지 않습니다.
- 도구 호출은 HUD 프로세스의 Guardrails 시간창 예산([시스템 도구](system-tools.md))과 중단 파일을 공유합니다. 별도 stdio 프로세스와 카운터를 합치는 전역 OS 서비스는 아닙니다.
- 모델 작업자와 응답 루프에 시간 한도를 두고 stop을 확인합니다. 도구별 자체 시간 한도도 적용합니다. 모델 작업자 종료가 Ollama GPU 작업의 즉시 중단을 보장하지 않습니다.
- 서버는 한 번에 응답 하나를 처리합니다. 같은 request ID는 모델/도구를 다시 실행하지 않습니다. 중단·실패를 완료로 표시하지 않습니다. 브라우저 연결 해제는 서버 작업 취소 명령이 아니며 진행 중 요청은 기존 한도 안에서 종료될 수 있습니다.
- 인식한 인증 키·비밀값·제어문자는 전송 전 거부하거나 결과에서 가립니다. 탐지는 최선 노력 방식이며 비밀번호·인증정보를 보내면 안 됩니다. DB는 암호화 저장소가 아닙니다.

Bearer 인증·정확한 로컬 Host와 Origin을 검사하고 POST에는 Origin이 필요합니다. 인증 없이 대화 기록을 읽거나 메시지를 보낼 수 없습니다. 토큰은 URL·쿠키·브라우저 영구 저장소에 넣지 않습니다. 모델 답변과 도구 결과를 HTML로 실행하지 않습니다.

## Claude 구독 두뇌

모델 이름 버튼에서 `Claude (구독) · sonnet` 또는 `Claude (구독) · opus`를 고르면, 채팅·음성 답변을 이 PC에 설치된 Claude Code CLI(`claude -p`)가 사용자의 Claude 구독으로 만듭니다. API 키는 쓰지 않습니다. 외부로 보내는 범위와 처음 고를 때의 확인은 [답하는 모델 고르기](#답하는-모델-고르기)를 따릅니다. 구현은 `jarvis/agents/claude_brain.py`입니다.

- 쓸 수 있는 조건: `claude`가 설치되어 있고 `claude auth status`가 claude.ai 구독 로그인(`authMethod: claude.ai`)을 보고할 때만 목록에서 고를 수 있습니다. 로그아웃 상태나 API 키 로그인은 이유와 함께 고를 수 없게 표시합니다. 상태 확인은 5초 안에 끝나지 않으면 실패로 보고, 실패는 5초, 성공은 30초 동안 다시 묻지 않습니다. 자식 프로세스 환경에서 `ANTHROPIC_*`와 `CLAUDE_CODE_USE_BEDROCK`·`CLAUDE_CODE_USE_VERTEX`·`CLAUDE_CODE_USE_FOUNDRY`를 지워 구독 밖 과금으로 넘어가지 않게 합니다.
- 답변 단계 하나마다 CLI 프로세스 하나를 띄웁니다. 내장 도구 없음(`--tools ""`, `--restricted`), MCP 서버 없음(`--strict-mcp-config`와 빈 설정), 권한 요청은 모두 거부(`--permission-prompts none`), 사용자·프로젝트 설정 무시(`--setting-sources ""`), 세션 저장 없음(`--no-session-persistence`), 빈 작업 폴더에서 실행합니다. `--bare`는 쓰지 않습니다(OAuth 로그인을 읽지 않아 구독이 동작하지 않습니다).
- 도구: Claude는 도구를 직접 부르지 않습니다. 로컬 모델과 같은 채팅 도구 고리(답변 형식의 `tool` 값)로만 도구를 요청하고, 자비스가 외부 허용 목록·노트와 웹 분리·근거 확인을 그대로 적용해 실행합니다. 그래서 도구 한 번마다 CLI 프로세스가 하나 더 뜹니다(답변당 최대 3회).
- 상한: 최대 2턴(`--max-turns 2`, 구조화된 답변 하나가 2턴), 채팅의 요청 기한, 출력 256KB, 입력 64KB, 중단 파일 확인. 어느 경우든 CLI와 그 하위 프로세스를 종료합니다.
- 실패는 짧은 이유로 표시하고 그 턴은 실패로 남습니다. 미설치·실행 실패(unavailable, 알 수 없는 실패는 종료 코드와 정리된 오류 한 줄), 로그인 필요(auth), 구독 사용 한도(rate_limited), 턴 초과(max_turns), 시간 초과(timeout), 형식 오류(invalid_response), 너무 큼(too_large). 다른 외부 모델로 자동 전환하지 않습니다.
- 구독 사용량: 답변 하나가 구독 한도(5시간 창 등)를 씁니다. 한도에 닿으면 풀릴 때까지 로컬 모델을 고르면 됩니다. 2026-10-29 시험 호출(짧은 인사, 도구 없음)은 API 시간 약 2.2초, 2턴이었습니다.
- 안정성 주의: 공식 문서는 `--bare`가 앞으로 `-p`의 기본값이 될 수 있다고 안내합니다. 그렇게 바뀌면 구독 로그인이 읽히지 않아 로그인 필요(auth)로 표시됩니다.

## API 키 두뇌

모델 이름 버튼에는 회사별 API 제공자 다섯 개가 있습니다: `Claude (API)`(Anthropic), `GPT (API)`(OpenAI), `Gemini (API)`(Google), `Grok (API)`(xAI), `DeepSeek (API)`. 사용자 본인의 API 키로 쓰며 **요금은 그 회사 계정에 청구됩니다**. 외부로 보내는 범위와 처음 고를 때의 확인은 [답하는 모델 고르기](#답하는-모델-고르기)와 같습니다. 구현은 `jarvis/agents/api_brain.py`, 키 저장은 `jarvis/core/credentials.py`입니다.

- 키 연결: 키가 없는 회사에는 비밀번호 입력칸과 **키 연결** 버튼이 보입니다. 키는 그 회사의 모델 목록 주소로 한 번 확인한 뒤 받아들여질 때만 Windows 자격 증명 관리자(이 PC, 현재 사용자, 이름 `JARVIS/brain/<제공자>`)에 저장됩니다. 화면·응답·로그·`brain.json` 어디에도 키를 다시 쓰지 않으며, 입력칸은 보내기 전에 비웁니다. `brain.json`에는 연결 이름만 남습니다. **키 삭제**는 자격 증명 관리자에서 지웁니다(그 모델을 고른 상태였다면 다음 질문은 실패로 남고 이유를 보여 줍니다).
- 모델 목록: 고정 목록이 없습니다. 키가 연결되면 회사의 모델 목록(Anthropic `GET /v1/models`, OpenAI `GET /v1/models`, Google `GET /v1beta/models`, xAI `GET /v1/language-models`, DeepSeek `GET /models`)을 10분 동안 기억해 보여 줍니다. OpenAI 목록에서는 임베딩·음성·이미지처럼 대화용이 아닌 이름을 뺍니다. 목록에 없는 모델은 **모델 ID 직접 입력**으로 고를 수 있습니다(영문·숫자·`._:/-`, 120자 이하).
- 형식 확인: 자비스 답변은 정해진 JSON 형식이어야 합니다. Anthropic 목록이 구조화 출력 미지원이라고 하는 모델은 고를 수 없습니다. 목록이 이를 알려 주지 않는 모델(OpenAI·xAI·DeepSeek·Gemini, 목록에 없는 직접 입력 모델)은 외부 사용 확인을 누른 **뒤에** 아주 짧은 확인 요청을 한 번 보내(스트리밍 + 한 칸짜리 JSON, 대화 내용 없음, 최대 1024 토큰) 통과해야 선택됩니다. 결과는 서버가 켜져 있는 동안 모델별로 기억하고, 시작할 때 자동으로 보내지 않습니다. 실패하면 이유를 보여 주고 지금 모델을 유지합니다.
- 답변: 모든 회사에 스트리밍으로 요청하고 답이 오는 대로 초안을 보여 줍니다. 회사마다 받는 JSON 스키마 기능이 달라(글자 수·항목 수 제한 미지원 등) 공통 부분만 보내고, **모든 답을 자비스가 원래 스키마 전체로 다시 검사**합니다. 맞지 않으면 형식 오류로 실패합니다. DeepSeek는 스키마 모드가 없어(JSON 모드만 있음) 스키마를 지시문에 넣고, 형식이 틀리면 초안 없이 **한 번만** 다시 요청합니다.
- 연결: 회사별 고정 주소(`api.anthropic.com`, `api.openai.com`, `generativelanguage.googleapis.com`, `api.x.ai`, `api.deepseek.com`)에만 HTTPS로 연결하고 인증서를 확인합니다. 리다이렉트와 환경 변수 프록시는 따르지 않습니다. 응답은 256KB, 대화는 64KB까지이고 요청 시간 제한과 중지 표시를 지킵니다. 새 패키지를 쓰지 않습니다(표준 라이브러리 `http.client`, `ctypes`).
- 실패: 키 거부(auth), 사용 한도(rate_limited), 모델 없음·거절·안전 중단(unavailable), 길이 제한에서 잘림(too_large), 형식 오류(invalid_response), 시간 초과(timeout). 회사가 보낸 오류 문장은 비밀값을 가린 한 줄(120자)만 붙입니다. 다른 모델로 자동 전환하지 않습니다.
- 사용한 공식 형식(2026-10-29 확인): Anthropic Messages `output_config.format`(`json_schema`) + SSE `text_delta`, 헤더 `x-api-key`·`anthropic-version: 2023-06-01`. OpenAI·xAI Chat Completions `response_format`(`json_schema`, `strict`) + SSE `choices[].delta.content`·`data: [DONE]`, 헤더 `Authorization: Bearer`; OpenAI 지시문은 `developer` 역할. Gemini `streamGenerateContent?alt=sse` + `generationConfig.responseMimeType`·`responseJsonSchema`, 헤더 `x-goog-api-key`, 생각 파트(`thought`)는 답에서 뺍니다. DeepSeek Chat Completions `response_format: json_object`.
- 나중 단계 후보: OpenAI·xAI의 Responses API, Gemini Interactions API(기본으로 서버에 저장하므로 지금은 쓰지 않음), 회사별 도구 호출.

## 실행 상태 수집기와 상황판

인증 후 상황판은 게시판의 담당·메시지·작업 기록을 5초마다 조회합니다. 정식·수습·후보를 구분하고, 완료된 과거 업무를 현재 업무로 표시하지 않습니다. 자기 보고와 직접 관찰은 별도 영역입니다. 창이 숨겨지거나 상황판을 접으면 조회를 멈추고, 연결 해제 시 내용과 토큰을 지웁니다. 갱신 실패 시 이전 표시가 과거 기록임을 알립니다.

`GET /api/activity`는 화면 연결 토큰과 정확한 로컬 Host·Origin 검사를 거칩니다. `POST /api/activity/runs/{run_id}/events`는 해당 실행에만 발급한 별도 Bearer 토큰을 사용하고, URL과 본문의 실행 ID 일치·JSON 1KB 상한·고정 필드·세대와 순번을 검사합니다. URL 쿼리와 다른 Origin은 거부하며, 서버 밖 등록 API는 제공하지 않습니다. 토큰 원문은 등록 시 한 번만 반환하고 저장소에는 해시만 보존합니다. 응답과 로그에 토큰을 넣지 않습니다.

`ActivityStore`는 서버마다 한 인스턴스로 재사용합니다. 프로세스 PID와 생성 시각을 확인한 자기 자신 또는 직접 자식만 등록합니다. 늦은 종료 보고도 이력에 보존하고, 낮은 세대의 보고는 새 실행을 덮지 못합니다. 재시작 이전 생존 신호는 미확인으로 표시합니다. 실행별 최대 512개 이벤트·전체 최대 200개 실행이며 자동 삭제하지 않고 상한 초과를 거부합니다. 현재 자동 등록은 HUD가 직접 시작하는 제한된 외부 협업 작업자(호출당 최대 180초, 10초 생존 신호)에 연결됩니다.

프로세스 생존·종료와 보고 수신은 관찰이며, 작업 단계·완료·실패는 실행기의 보고입니다. 어느 것도 검증 통과를 의미하지 않습니다. 검증 어댑터는 아직 연결하지 않아 검증 근거를 만들지 않습니다. 자동 재실행·재배정·종료, 전체 데스크톱 Codex/Claude/Cursor 세션의 내부 상태 자동 추적, 원격 접속, 실제 토큰 스트리밍은 포함하지 않습니다. 이 가드레일은 OS 보안 격리가 아닙니다. Windows 파이프 입력 전송이 막힐 때 기한 점검이 늦어질 수 있는 기존 한계는 별도 과제이며, 강제 종료나 외부 서버 과금 중단을 보장하지 않습니다.

## 등록된 프로세스 경고

외부 작업의 콘솔 표시 준비: `python -m jarvis.cli.worker_view --conversation-id <ID> --request-id <ID>`는 해당 요청의 고정 진행 기록만 읽습니다. 모델을 호출하거나 실패 요청을 다시 실행하지 않습니다. 별도 창은 시작·결과·실패 관찰을 표시하며 Claude 자체의 대화형 TUI나 토큰 단위 스트리밍은 아닙니다. 실제 생산자 연결과 계정 가용성 확인은 별도이며, 로그가 없으면 대기로 표시합니다.

새 HUD 서버는 시작할 때 자기 PID·생성 시각·부모 신원과 실행 상한 7일을 등록합니다. 연결된 화면은 인증된 `/api/processes`에서 최대 100개의 등록 기록을 30초마다 확인합니다. 부모 프로그램 종료, 실행 상한 초과, PID 재사용, 상태 확인 불가를 구분해 경고하며 자동 종료·재시작하지 않습니다. 부모 종료는 관찰 결과이며 의도적으로 분리한 서비스에서도 나타날 수 있습니다.

조회 실패는 정상으로 표시하지 않습니다. 화면에는 프로세스 이름·PID·경고만 표시하며 명령줄·저장 경로·부모 신원은 전달하지 않습니다. 연결 해제와 샘플 모드에서는 실제 경고를 지웁니다. 등록되지 않은 기존 프로세스와 모든 pytest 실행을 자동 발견하는 기능은 아닙니다. 이전 서버는 재시작해야 등록과 새 조회 경로가 반영됩니다.

## OpenRig 참고 범위

사용자가 지정한 [mvschwarz/openrig](https://github.com/mvschwarz/openrig)의 `0b1d8b3dc1b418f1568e571b1df174041fed77f2` 소스를 내려받았습니다. Apache-2.0 라이선스 원문은 참고 소스에 유지합니다. daemon의 routes/chat.ts, domain/chat-repository.ts, domain/ask-service.ts에서 **대화 저장 / 요청 경계 / 실행 주체 분리**를 참고했습니다. 기존 Python·Starlette·Ollama 구조에 맞춰 새로 작성했으며 TypeScript 코드를 복사하지 않았습니다.

OpenRig 전체 daemon/tmux 런타임은 설치·가동하지 않았습니다. 현재 채팅과 역할별 협업은 자비스 자체 구현으로 동작합니다. 이후 추가한 로컬 리드와 Codex 작업자 연결의 실제 검증 및 Claude 미검증 상태는 [협업 안내](hybrid-team.md)를 따릅니다. 자동 화면은 로컬 협업 제안까지 지원하며 기존 개발 작업의 코드 실행·파일 적용을 자동 수행하지 않습니다.

동명이인 확인 단계에서 받은 EliasOenal/OpenRig 참고본도 라이선스와 함께 artifacts/references에만 보존하며 실행 코드에는 사용하지 않습니다. REA는 기존 JS/PE 분석용 도구입니다. 공개 GitHub TypeScript 원문은 직접 읽을 수 있어 역공학 추출이 필요하지 않았습니다.


## Codex 세션 이벤트 표시

인증된 `GET /api/sessions`는 로컬 `.jarvis-sessions/sessions.sqlite3`의 선언만 읽습니다. HUD의 외부 세션 보고는 응답 시작·도구 시작/종료·승인 대기·응답 종료·중단을 표시하며, 연결 해제 때 지웁니다. 표시된 단계는 `self_reported`, 서버 수신 시각만 `observed`입니다. 직원 신원·모델 내부 상태·실제 온라인 여부·작업 성공·검증 통과를 입증하지 않습니다. 오래된 보고도 오프라인으로 단정하지 않습니다.

수신기는 Codex 이벤트에서 허용된 종류와 안전한 세션/턴/이벤트 ID만 저장합니다. 프롬프트·명령·도구 인자/출력·작업 경로는 저장하지 않습니다. 경로는 입력 범위를 확인할 때만 사용합니다. 턴 ID 없는 턴 이벤트는 수신기에서 버립니다. 이벤트 ID 중복은 상태와 수신 시각을 갱신하지 않으며, 종료된 턴의 늦은 도구 이벤트는 재활성화하지 않습니다. 플랫폼 순번이 없어 처음 도착하는 서로 다른 턴의 정확한 발생 순서는 보장하지 않습니다.

저장 상한은 200세션·20,000이벤트·16MiB이며 초과 시 기존 자료를 지우지 않고 새 기록을 거부합니다. 기본 잠금 대기는 2초이고 hook 전용으로 짧게 설정할 수 있습니다. 수신기는 실패 시 본래 작업을 막지 않는 방식이므로 잠금·오류·hook 기한 초과 때 보고가 유실될 수 있습니다. 전달 보장을 제공하지 않습니다.

`python -m jarvis.cli.session_signal --help`의 렌더링 기능은 설정 예시를 출력할 뿐 설치·신뢰 승인·자동 활성화를 하지 않습니다. 실제 Codex hook 설치·신뢰와 새 세션 시작은 별도 단계입니다. 현재 CLI→저장→인증 화면 확인은 고정 시험 이벤트로 수행했으며, 데스크톱의 자동 보고가 검증됐다는 뜻은 아닙니다. 기존 서버는 새 코드로 다시 시작해야 API와 화면이 반영됩니다.


공통 저장소는 `codex`와 `claude-code`의 고정 이벤트 계약을 받으며 직원별 세션/턴을 분리합니다. Claude 수신기 자체는 별도 구현이므로 저장소 허용만으로 실제 자동 수신을 보장하지 않습니다. 한도에 도달하면 인증 조회의 `capacity`와 화면에 이벤트 저장/새 세션 등록 중단을 알립니다. 기존 기록을 자동 정리하거나 삭제하지 않습니다. 단독 도구 보고만 수신한 세션은 상태 미확인으로 남을 수 있으며 실제 활동을 입증하지 않습니다. 같은 턴의 첫 종료 보고는 유지하고, 세션 재개 뒤 옛 종료 보고나 반복 시작 보고가 현재 단계를 되돌리지 못하게 합니다.
