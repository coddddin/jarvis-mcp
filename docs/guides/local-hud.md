# 자비스 로컬 작업 화면

2026-10-20부터 같은 화면에 [전용 채팅](chat.md) 탭이 추가됐습니다. 아래 읽기 전용 설명은 작업 현황 탭에 해당합니다. 저장 작업이 없어도 채팅 화면은 시작할 수 있습니다.

Phase 3 첫 구현인 읽기 전용 화면입니다. 저장된 작업의 계획 → 작성 → 검증 단계, 최근 QA 결과, 예약 예산, 이벤트 기록을 표시합니다. 기존 MCP 서버와 별도 프로세스로 실행하며 MCP 27개 도구 계약은 그대로입니다.

## 실행과 연결

1. 프로젝트의 `scripts/start-hud.cmd`를 실행합니다. 서버 준비 후 기본 브라우저가 열립니다. 창을 닫거나 Ctrl+C로 서버를 종료합니다.
2. `http://127.0.0.1:8787`에서 **연결 파일 선택**을 누릅니다.
3. 프로젝트 `.jarvis-auth/agent-events-token.txt`를 선택합니다. 내용은 채팅에 붙여넣지 않습니다. 파일이 없으면 화면 서버가 최초 실행 때 생성합니다.
4. 작업을 선택하면 해당 작업의 기록을 불러옵니다. **새로고침**은 상태를 재조회하고 기록 연결을 다시 엽니다. **연결 해제**는 창의 인증값과 작업 표시를 비웁니다. 브라우저 페이지 자체를 새로고침해도 다시 파일을 선택해야 합니다.

서버는 시작 시 최근 작업 최대 8개의 ID만 등록합니다. 새 작업을 포함하려면 서버를 다시 시작합니다. 저장된 작업이 없으면 안내하고 종료하며 임의 작업을 만들지 않습니다. **샘플로 둘러보기**는 명확히 표시한 예시이며 모델이나 작업 API를 호출하지 않습니다.

명시적으로 작업을 지정하거나 포트를 바꾸려면 프로젝트 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m jarvis.cli.hud --port 8787 --task-id <작업ID> --open
```

`--task-id`는 최대 32개까지 반복 지정합니다. `--open`을 생략하면 브라우저를 자동으로 열지 않습니다. 다른 포트를 쓰면 표시한 주소로 접속합니다. 기본 허용 출처는 정확한 `http://127.0.0.1:<포트>`이므로 localhost로 바꿔 접속하지 않습니다.

## 표시 범위

- 작업 제목은 요청 요약 앞 100자입니다. 전체 요청·소스 코드·수정 제안·사용자 피드백·기억 저장소를 내려보내지 않습니다.
- 검증은 실제 저장된 증거의 검사 종류와 통과 개수입니다. 구문 검사는 기능 검증과 구분합니다. 검증 통과가 일반 프로젝트 전체의 정확성을 뜻하지 않습니다.
- 예산은 컨텍스트와 생성 상한의 **예약량**이며 실제 사용량이 아닙니다.
- 이벤트는 상태 요약입니다. 에이전트 전체 대화나 내부 사고 과정이 아닙니다. 이벤트 도입 이전 작업은 현재 상태만 표시합니다.
- 선택한 작업의 이벤트를 구독합니다. 다른 작업의 최신 상태는 새로고침으로 확인합니다. 기록은 최대 32개 보관하고 최근 14개를 표시합니다.

## 경계와 오류

서버는 127.0.0.1에만 바인딩합니다. 상태 API는 Bearer 인증, WebSocket은 허용 출처·작업 목록과 첫 인증 프레임을 검증합니다. 연결값은 URL·브라우저 저장소·로그에 넣지 않으며 외부 서비스로 게시하지 않습니다. 연결 파일은 로컬 접근 자격이므로 공유하지 않습니다. 이는 Windows 사용자별 로그인이나 다른 로컬 프로세스의 접근을 차단하는 OS 보안 기능은 아닙니다.

이 화면에서 작업 생성·모델 실행·파일 변경·코드 적용은 제공하지 않습니다. `.jarvis-stop`이나 손상된 상태 저장소는 빈 성공 목록으로 숨기지 않고 조회 실패를 표시합니다. 명시적으로 삭제한 작업은 목록에서 빠집니다. 기록 순서 오류는 경고하며 완료 상태를 임의로 만들지 않습니다. 일시적인 연결 종료는 최대 3회 재연결하고 실패하면 새로고침을 안내합니다.

정상적인 대기 시간 종료는 실패 횟수에 포함하지 않고 연결을 계속 순환합니다. 완료 작업의 기록도 최종 순번까지 받기 전에 끊기면 이어받습니다. 순번/형식 오류는 자동 반복을 멈추고 **새로고침** 시 현재 상태를 기준으로 이후 기록부터 다시 연결합니다. 건너뛴 과거 기록을 복구 완료로 표시하지 않습니다.

작업 흐름 아래의 갱신 속도는 최근 전경 표본 최대 64개의 p95입니다. 이벤트 발행 시각부터 DOM 갱신 후 두 번째 애니메이션 프레임까지 측정한 근사치이며 실제 모니터 출력 시간을 측정하는 장비 계측은 아닙니다. 과거 기록·끊긴 동안의 재생·샘플 모드·백그라운드는 제외합니다. 작업 전환·연결 해제·화면 가시성 변경 시 측정을 초기화합니다. 작은 표본과 현재 PC의 값이며 모든 환경의 지연 보장이 아닙니다.

음성, 화면 공유, 3D 지식 탐색, 모델 전환, 모닝 브리핑은 다음 단위입니다. 첫 전경 표본의 화면 반영 계측은 구현했으며, 다양한 부하·느린 연결의 종합 성능 계측은 후속 항목입니다. 무지연을 보장하지 않습니다.
