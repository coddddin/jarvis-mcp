# 자비스 로컬 작업 화면

2026-10-20부터 같은 화면에 [전용 채팅](chat.md) 탭이 추가됐습니다. 아래 읽기 전용 설명은 작업 현황 탭에 해당합니다. 저장 작업이 없어도 채팅 화면은 시작할 수 있습니다.

Phase 3 첫 구현인 읽기 전용 화면입니다. 저장된 작업의 계획 → 작성 → 검증 단계, 최근 QA 결과, 예약 예산, 이벤트 기록을 표시합니다. 기존 MCP 서버와 별도 프로세스로 실행하며 MCP 27개 도구 계약은 그대로입니다.

## 실행과 연결

1. 프로젝트의 `scripts/start-hud.cmd`를 실행합니다. 서버 준비 후 기본 브라우저가 열리고 **자동으로 연결**됩니다. 창을 닫거나 Ctrl+C로 서버를 종료합니다.
2. 자동 연결이 안 되면(5분이 지났거나 주소를 직접 열었을 때) **연결 파일 선택**을 누르고 프로젝트 `.jarvis-auth/agent-events-token.txt`를 선택합니다. 내용은 채팅에 붙여넣지 않습니다. 파일이 없으면 화면 서버가 최초 실행 때 생성합니다.
3. 작업을 선택하면 해당 작업의 기록을 불러옵니다. **새로고침**은 상태를 재조회하고 기록 연결을 다시 엽니다. **연결 해제**는 창의 인증값과 작업 표시를 비웁니다. 같은 탭에서 페이지를 새로고침하면 다시 연결되고, 탭을 닫거나 연결 해제하면 잊습니다.

자동 연결은 브라우저 주소의 `#connect=` 뒤에 붙은 **한 번만 쓰는 코드**로 동작합니다. 연결 파일의 값은 주소에 넣지 않습니다. 이 코드는 서버를 켤 때마다 새로 만들고 5분 뒤나 한 번 쓰면 버리며, 틀린 시도가 5번이면 막힙니다. 페이지는 코드를 읽자마자 주소창에서 지우고 먼저 코드로 연결합니다. 코드가 이미 쓰였으면 이 탭에 저장된 연결값으로 다시 시도하고, 그 값도 맞지 않으면 지웁니다. 새로고침용 연결값은 그 탭의 세션 저장소에만 둡니다.

서버는 시작 시 최근 작업 최대 8개의 ID만 등록합니다. 새 작업을 포함하려면 서버를 다시 시작합니다. 저장된 작업이 없으면 안내하고 종료하며 임의 작업을 만들지 않습니다. **샘플로 둘러보기**는 명확히 표시한 예시이며 모델이나 작업 API를 호출하지 않습니다.

명시적으로 작업을 지정하거나 포트를 바꾸려면 프로젝트 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m jarvis.cli.hud --port 8787 --task-id <작업ID> --open
```

`--task-id`는 최대 32개까지 반복 지정합니다. `--open`을 생략하면 브라우저를 자동으로 열지 않습니다. 다른 포트를 쓰면 표시한 주소로 접속합니다. 기본 허용 출처는 정확한 `http://127.0.0.1:<포트>`이므로 localhost로 바꿔 접속하지 않습니다.

## 표시 범위

- 작업 제목은 요청 요약 앞 100자입니다. 전체 요청·소스 코드·수정 제안·사용자 피드백·기억 저장소를 내려보내지 않습니다.
- 검증은 실제 저장된 증거의 검사 종류와 통과 개수입니다. 구문 검사는 기능 검증과 구분합니다. 검증 통과가 일반 프로젝트 전체의 정확성을 뜻하지 않습니다.
- 예산은 컨텍스트와 생성 상한의 **예약량**이며 실제 사용량이 아닙니다.
- 이벤트는 상태 요약입니다. 에이전트 전체 대화나 내부 사고 과정이 아닙니다. 이벤트 도입 이전 작업은 현재 상태만 표시합니다.
- 선택한 작업의 이벤트를 구독합니다. 다른 작업의 최신 상태는 새로고침으로 확인합니다. 기록은 최대 32개 보관하고 최근 14개를 표시합니다.

## Ollama 카드

연결 후 화면은 인증된 `GET /api/model-status`로 모델 서버의 **마지막 관찰**을 읽습니다. 다른 상태 API와 같은 Bearer·Host·Origin 검사와 쿼리 거부를 먼저 통과해야 하며, 서버는 그 다음에만 고정된 `127.0.0.1:11434`에 `GET /api/tags` 한 번을 보냅니다. 확인 대상은 채팅 설정의 검증된 모델 이름뿐이고 주소·모델을 요청으로 바꿀 수 없습니다. 채팅이 없거나 모델 이름이 유효하지 않으면(cloud 포함) 조회하지 않고 503을 돌려줍니다.

- **실행 중 · 모델 있음**: 서버가 응답했고 설치 목록에 설정 모델이 있습니다. 모델이 메모리에 올라왔거나 답변·채팅이 성공한다는 뜻은 아닙니다.
- **실행 중 · 모델 없음**: 서버는 응답했지만 목록에 모델이 없습니다. 자동으로 내려받지 않습니다.
- **연결 안 됨**: 연결이 거부됐습니다. **알 수 없음**: 시간 초과·비정상 응답·형식 오류·이전 버전 서버(404)입니다. 꺼졌다는 뜻이 아닙니다.

패널 아래 한 줄 안내("확인하지 못하면 '알 수 없음'으로 보여요. 꺼졌다는 뜻은 아니에요.")가 세 카드 공통 주의 문구입니다. 카드마다 같은 경고를 반복하지 않습니다.

결과는 서버 메모리에 약 10초 보관하고 동시 요청은 한 번의 조회를 공유합니다. 소켓 제한 시간 2초는 각 소켓 동작마다 적용되며 전체 조회 시간의 절대 상한은 아닙니다. 응답 본문·오류 문구·다른 설치 모델 목록은 내려보내지 않습니다. 화면은 기존 30초 주기와 화면 복귀 때만 다시 읽고, 숨김·연결 해제 중에는 호출하지 않으며 연결 해제·새 연결 파일에서 즉시 알 수 없음으로 되돌립니다. 화면 연결이나 모델 이름만으로 모델 상태를 추정하지 않습니다.

## 실행 추적 조회 API (J1-TRACE)

`GET /api/activity/tasks/<task_id>/trace`는 실행 관찰 저장소의 기존 `ActivityStore.trace`를 그대로 읽어 돌려줍니다. 아직 화면에서 호출하는 곳이 없습니다.

- **식별자 범위**: `task_id`는 실행 관찰(Activity)에 등록할 때 쓴 32자리 소문자 16진수입니다. Board 작업 ID, 서버에 등록한 작업 목록(TaskStore)의 ID, 팀 실행의 요청 ID와 같은 값이 아닙니다. 형식이 다르면 저장소를 읽지 않고 400 `invalid_activity_task`입니다.
- **인증**: `GET /api/activity`와 같은 검사입니다. 정확한 Host, 허용 Origin(없으면 허용), 쿼리 거부, 화면 연결값 Bearer를 먼저 통과해야 저장소에 접근합니다. 실행 보고용 토큰과 한 번 쓰는 연결 코드로는 조회할 수 없습니다. 화면 연결값은 이미 `/api/activity`로 모든 실행을 읽을 수 있으므로 이 경로가 조회 범위를 넓히지 않으며, 등록된 작업 목록으로 제한하지도 않습니다.
- **읽기 전용**: GET만 등록했고 저장소를 바꾸지 않습니다. 실행 보고 접수(`POST /api/activity/runs/<run_id>/events`)는 그대로입니다. 저장소가 없거나 읽기에 실패하면 세부 내용 없이 503 `activity_unavailable`이며, 빈 성공으로 돌려주지 않습니다.
- **작업 증명 아님**: 기록이 없는 ID는 `status: unknown`과 빈 `runs`로 답합니다(404 아님). 시작·종료·결과 참조는 직원의 자체 보고이고 `verified`는 항상 빈 목록입니다. 순번 누락, 이전 실행 차단(fenced), 수집기 재시작은 표시만 하며 성공이나 Board 완료로 해석하지 않습니다.
- **상한**: 저장소의 고정 상한(실행 200개, 한 번의 추적 전체에서 이벤트 512개)을 넘으면 `has_more`로 표시합니다. 요청으로 개수·경로·주소를 바꿀 수 없습니다.

## 경계와 오류

서버는 127.0.0.1에만 바인딩합니다. 상태 API는 Bearer 인증, WebSocket은 허용 출처·작업 목록과 첫 인증 프레임을 검증합니다. 연결값은 URL·로그에 넣지 않고 브라우저에는 현재 탭의 세션 저장소에만 두며, 외부 서비스로 게시하지 않습니다. 연결 파일은 로컬 접근 자격이므로 공유하지 않습니다. 이는 Windows 사용자별 로그인이나 다른 로컬 프로세스의 접근을 차단하는 OS 보안 기능은 아닙니다.

이 화면에서 작업 생성·모델 실행·파일 변경·코드 적용은 제공하지 않습니다. `.jarvis-stop`이나 손상된 상태 저장소는 빈 성공 목록으로 숨기지 않고 조회 실패를 표시합니다. 명시적으로 삭제한 작업은 목록에서 빠집니다. 기록 순서 오류는 경고하며 완료 상태를 임의로 만들지 않습니다. 일시적인 연결 종료는 최대 3회 재연결하고 실패하면 새로고침을 안내합니다.

정상적인 대기 시간 종료는 실패 횟수에 포함하지 않고 연결을 계속 순환합니다. 완료 작업의 기록도 최종 순번까지 받기 전에 끊기면 이어받습니다. 순번/형식 오류는 자동 반복을 멈추고 **새로고침** 시 현재 상태를 기준으로 이후 기록부터 다시 연결합니다. 건너뛴 과거 기록을 복구 완료로 표시하지 않습니다.

작업 흐름 아래의 갱신 속도는 최근 전경 표본 최대 64개의 p95입니다. 이벤트 발행 시각부터 DOM 갱신 후 두 번째 애니메이션 프레임까지 측정한 근사치이며 실제 모니터 출력 시간을 측정하는 장비 계측은 아닙니다. 과거 기록·끊긴 동안의 재생·샘플 모드·백그라운드는 제외합니다. 작업 전환·연결 해제·화면 가시성 변경 시 측정을 초기화합니다. 작은 표본과 현재 PC의 값이며 모든 환경의 지연 보장이 아닙니다.

음성, 화면 공유, 3D 지식 탐색, 모델 전환, 모닝 브리핑은 다음 단위입니다. 첫 전경 표본의 화면 반영 계측은 구현했으며, 다양한 부하·느린 연결의 종합 성능 계측은 후속 항목입니다. 무지연을 보장하지 않습니다.
