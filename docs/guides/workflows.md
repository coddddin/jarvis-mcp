# 작업 환경 런처 — 등록·미리보기·실행·상태·종료

[문서 안내](../README.md) · [현재 계획](../PLAN.md)

## 제공하는 도구

- `list_workflows()`: 등록된 작업 묶음과 활성화 여부.
- `preview_workflow(name)`: 실행할 프로그램·고정 인자·작업 위치·URL 검토.
- `start_workflow(preview_id)`: 한 번 쓰는 미리보기에 연결된 작업 실행.
- `get_workflow_status(run_id)`: 실행 단계·서비스 프로세스 상태·오류 조회.
- `list_workflow_runs()`: 실행 기록과 현재 서버의 소유 여부 조회.
- `stop_workflow(run_id)`: 현재 서버가 시작하고 소유를 확인할 수 있는 서비스 종료.

각 도구는 `jarvis/features/workflows/tools/`의 독립 파일이고 `jarvis/features/workflows/service.py`의 공유 서비스를 사용합니다. 런처 도구는 6개이며 현재 전체 도구 수는 27개입니다.

## 실행 예제

현재 기본 작업은 `local-status`입니다. 파일을 읽거나 제공하지 않는 상태 서버를 127.0.0.1:8765에 기동하고 브라우저 탭 하나를 여는 예제입니다. 기본 실행 시간은 1시간입니다.

1. 자비스를 재연결해 새 도구를 불러옵니다.
2. “자비스 등록된 작업 목록 보여줘”로 확인합니다.
3. `preview_workflow(name="local-status")`의 프로그램·인자·주소를 확인합니다.
4. 사용자가 그 작업 실행을 요청한 범위에서 반환된 preview_id로 start를 호출합니다.
5. 반환된 run_id로 상태를 확인하고 필요할 때 stop을 호출합니다.

`jarvis-development`는 현재 자비스 코드 폴더를 VS Code로 열고 파일을 제공하지 않는 127.0.0.1:8766 상태 페이지를 엽니다. Python MCP 서버는 stdio 연결을 유지하며 이 페이지는 웹 개발 서버나 HUD가 아닙니다. 2026-10-17 실제 MCP 호출로 앱 실행 요청·브라우저 전달·HTTP 200 응답·상태 조회·소유 서비스 종료까지 확인했습니다. 앱 창의 표시 자체는 자동 확인하지 않았습니다. 검증용 서비스는 종료했습니다.

## 운영자 등록 방식

설정은 **코드 영역의 `config/workflows.json`**에 둡니다. 문서 데이터 작업공간의 설정을 읽거나 도구 인자로 임의 실행 파일·명령 문자열을 받지 않습니다. 등록 편집용 MCP 도구도 제공하지 않습니다.

- `programs`: 프로그램 ID와 절대 실행 파일 경로. `@python`은 현재 Python, `@vscode`는 표준 Windows 설치 위치, `@status-server`는 고정된 파일 미제공 상태 서버입니다.
- `allowed_hosts`: 웹 동작의 시작 URL에 허용할 정확한 호스트명. 와일드카드나 임의 URL 인자는 지원하지 않습니다.
- `profiles`: 작업 이름·설명·활성화 여부·실행 시간 제한과 고정 동작 목록.
- 동작 `service`: 등록 프로그램·인자 배열·작업공간 내부 cwd·준비 확인용 loopback TCP 포트.
- 동작 `app`: 등록 GUI 앱. UI 동작과 기존 인스턴스 전달 여부를 보증하지 않고 종료 대상으로 삼지 않습니다.
- 동작 `web`: 등록 URL의 브라우저 전달. HTTPS 허용 호스트 또는 HTTP loopback만 허용하고 file/javascript·인증정보 포함 URL을 거부합니다.

기존 `development-template`을 사용자 선택에 따라 `jarvis-development`로 설정했습니다. VS Code는 확인된 설치 파일의 절대 경로, 열 프로젝트는 현재 코드 루트의 고정 인자를 사용합니다. cwd는 데이터 작업공간 내부로 유지하며 일반 경로 검증을 확대하지 않습니다. 다른 PC로 이전하면 programs의 VS Code 경로와 프로젝트 인자를 수정해야 합니다.

임의 셸은 사용하지 않으며 .cmd/.bat/.ps1/.sh/.py 파일을 직접 실행 프로그램으로 등록할 수 없습니다. cmd·PowerShell·bash·스크립트 호스트도 거부합니다. Python·다른 실행 파일의 **운영자가 등록한 고정 인자**는 실행되므로 설정 자체는 신뢰된 코드에 준합니다. 기존 제한 셸 도구의 허용 목록을 확대하지 않습니다.

설정·인자·URL에 비밀키·인증 토큰을 넣지 마세요. 미리보기에 등록 인자와 URL이 표시됩니다. 현재 별도 비밀정보 주입 기능은 없습니다. 기본 자식 환경에는 일반 OS·앱 경로 변수만 전달하고 API 키 등 임의 환경변수를 상속하지 않습니다.

## 실행과 실패 정책

- 미리보기는 10분·한 번 사용·재시작 시 무효입니다. 실행 전 설정 해시·실행 파일 메타데이터·기본 상태 서버 코드 해시·cwd를 다시 확인합니다.
- 같은 서버에서 같은 작업의 중복 실행을 거부하고 동시에 실행 중인 작업은 최대 5개입니다. 다른 서버·기존 앱의 전역 중복 제어는 아닙니다.
- 서비스 포트가 이미 열려 있으면 기존 프로세스를 채택하거나 종료하지 않고 거부합니다. 프로세스 기동 뒤 최대 1~10초 설정값 동안 loopback TCP 응답을 확인합니다. TCP 응답만으로 업무 기능의 정상·포트의 독점 소유를 보증하지 않습니다.
- 시작 실패·시간 초과·중단은 단계별 결과와 오류를 반환하고 이번 실행의 소유 서비스만 정리합니다. 이미 열린 GUI 앱·브라우저 탭은 되돌리지 않습니다. 실행 전체가 원자적 트랜잭션은 아닙니다.
- 브라우저 전달은 최대 2초 기다립니다. 시간 초과 시 서비스는 정리하되 브라우저 호출을 강제 취소하지 못하므로 탭이 늦게 열릴 수 있음을 오류에 명시합니다. 전달 수락은 페이지 로딩·UI 성공을 의미하지 않습니다. 브라우저의 후속 리디렉션은 런처가 제어하지 않습니다.
- 표준 출력·오류는 DEVNULL로 보내며 서비스 로그 수집은 이번 범위에 포함하지 않습니다. 실패는 exit code·단계·정제한 메시지로 확인합니다.
- stop은 자식 프로세스 핸들과 생성 시각을 확인하고 현재 확인할 수 있는 서비스 하위 프로세스를 정리합니다. PID가 바뀌었거나 접근할 수 없으면 임의 종료하지 않고 실패를 보고합니다. 서비스가 이미 종료된 뒤 남은 재부모화 자식이나 동시에 생성되는 하위 프로세스를 완전히 추적하는 OS Job 격리는 없습니다.

## 실행 시간·중단·재시작

- 서비스 실행 시간 상한은 기본 3600초, 등록 범위는 1~86400초입니다. 기동 중에도 상한을 확인합니다.
- 감시 스레드가 약 0.25초 간격으로 실행 시간과 `.jarvis-stop`을 확인해 소유 서비스 정리를 시도합니다. 개별 OS 호출의 즉시 취소·정확한 종료 지연 보장은 아닙니다. GUI 앱·탭은 유지합니다.
- 정상적인 Python 서버 종료 시 atexit 정리를 시도합니다. 프로세스 강제 종료·전원 장애 시에는 감시·atexit가 동작하지 않아 서비스가 남을 수 있습니다. 운영자가 확인해야 하며 OS 수준 수명 격리는 후속 과제입니다.
- 실행 기록은 `.jarvis-workflows/<run_id>.json`에 최대 100개 보관합니다. 자동 삭제하지 않습니다.
- 서버 재시작 후 기록은 과거 정보로만 표시합니다. 과거 PID를 소유 권한으로 간주하지 않으므로 새 서버가 그 PID를 종료하지 않습니다. 불명확한 프로세스는 운영자가 확인합니다.
- 새 도구도 공통 시간창 호출 예산을 공유하며 시작·종료는 민감 등급입니다([시스템 도구](system-tools.md)). 내부 준비 확인·감시·정리는 추가 도구 호출로 차감하지 않습니다. 예산이 끝나도 감시는 유지하며 운영자는 중단 파일로 관리 서비스 정리를 요청할 수 있습니다.

## 보안 경계와 남은 범위

cwd 제한과 등록 목록은 OS 샌드박스가 아닙니다. 등록한 Python·앱·개발 서버는 운영체제 사용자 권한으로 동작하고 자체적으로 파일·네트워크에 접근할 수 있으므로 실행 대상·인자·노출 주소를 운영자가 검토해야 합니다. 두 상태 프로필 모두 파일을 제공하지 않습니다. 브라우저의 유휴 사전 연결이 다른 요청을 막지 않도록 상태 서버는 연결별 스레드로 처리합니다.

음성 문구, 작업 예약, 시작 프로그램 등록, 사용자별 개발 프로필 자동 탐색, 비밀키 관리, 서비스 로그·HTTP 기능 건강 검사, OS Job 격리는 미구현입니다. 읽기 전용 에러 분석은 [별도 안내](debug-assistant.md)를 따르며 등록형 웹 수집은 [별도 안내](web-information.md)를 따릅니다.

## 검증
