# 0002. 로컬 임베딩 모델과 하이브리드 검색 가중치

[문서 안내](../README.md) · [ADR 0001 하드웨어 자원](0001-hardware-resource-policy.md)

- 상태: 채택(코어). 기본값은 데이터로 정했고, 채팅 연결(보드 2e3093a2 5-6단계)에서 켠다.
- 결정일: 2026-11-17. 근거: `scripts/rag_eval` 측정 결과. 벡터 RAG 도입은 사용자 결정이다(보드 2e3093a2).

## 배경

기존 지식 검색은 어휘 해싱이다. 단어 2글자 조각이 겹쳐야 찾는다. 그래서 "말로 명령하는 기능"으로는 "로컬 음성" 문서를 못 찾는다.

후보 모델 두 개는 모두 설치되어 있다. 둘 다 1024차원이다.

- `qwen3-embedding:0.6b`: 약 0.64GB, Q8_0. 질문에는 지시문 접두어를 붙인다.
- `bge-m3:latest`: 약 1.16GB, F16.

## 측정 (2026-11-17)

- 질문: 한국어 20개. 14개는 docs/, 6개는 합성 Vault 노트 8개가 대상이다.
- 질문은 대상 문서와 단어가 거의 겹치지 않게 바꿔 썼다.
- 관련성은 파일 단위로 판정한다.
- 색인: 문서 63개(docs/ 55개, Vault 8개), 704조각.

| 방법 | recall@5 | MRR |
|---|---|---|
| 어휘만 | 0.40 | 0.158 |
| 임베딩만, qwen3-embedding:0.6b | 0.95 | 0.885 |
| 임베딩만, bge-m3 | 0.90 | 0.779 |
| 하이브리드 qwen3, 어휘 가중치 1.0 | 0.60 | 0.453 |
| 하이브리드 qwen3, 어휘 가중치 0.25 | 0.95 | 0.689 |
| 하이브리드 qwen3, 어휘 가중치 0.1 | 0.95 | 0.762 |
| 하이브리드 bge-m3, 어휘 가중치 0.1 | 0.90 | 0.738 |

두 순위를 같은 가중치로 RRF 융합하면, 어휘 쪽의 잡음 순위가 좋은 임베딩 순위를 밀어낸다.

## 결정

- 기본 모델은 `qwen3-embedding:0.6b`다(`DEFAULT_EMBED_MODEL`). 점수가 가장 높고 GPU 몫이 bge-m3의 절반이다.
- `keep_alive`는 2분이다. 묶음 16개, 입력 하나는 2000자까지다.
- 하이브리드 융합에서 어휘 순위의 가중치는 0.1이다(`LEXICAL_WEIGHT`). 임베딩 순위는 1.0이다.
  - 이번 질문 묶음에서는 어휘가 점수를 올리지 않는다.
  - 그래도 남긴다. 파일명, 작업 ID, 오류 코드처럼 정확히 같은 글자를 찾는 질문을 구하기 위해서다.
- Ollama나 모델이 없거나 벡터가 덜 만들어졌으면 어휘 검색으로 돌아간다. 결과의 `retrieval.fallback_reason`에 이유를 적는다.
- 저장소 기본값은 임베딩 꺼짐(`embed_model=None`)이다. 기존 MCP 도구와 테스트는 모델을 부르지 않는다.

## 한계와 다음 단계

- 질문 20개는 작다. 정확한 식별자를 찾는 질문이 없어서 어휘 가중치 0.1의 근거는 약하다.
  - 식별자 질문을 넣어 다시 재 볼 것.
